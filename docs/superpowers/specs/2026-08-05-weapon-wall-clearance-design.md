# 枪械贴墙碰撞与自动抬枪设计

## 状态

已按最终评审决策修订，待用户复核。

## 背景

玩家当前使用 `CharacterBody3D`，主体移动碰撞为半径 `0.45m`、总高 `1.8m` 的竖直胶囊体，碰撞遮罩只包含场景墙体所在的第 1 层。角色 GLTF 内置 `Pistol`、`Rifle`、`Knife` 等武器网格；Godot 导入后，这些网格位于左手 `Middle1_L` 的 `BoneAttachment3D` 下。装备系统通过武器定义中的 `visual_node_name` 找到对应网格，远程武器运行节点继续跟随该网格的全局变换。

当前枪械只有视觉模型和枪口反馈，没有用于墙体阻挡的体积。人物主体尚未接触墙体时，枪身和枪口已经可能穿进墙体。模型包含 `Idle_Gun`、`Run_Gun`、`Walk_Gun` 等正常持枪动画，但没有独立的高位持枪挂点或抬枪动画。

## 目标

- 用贴合当前枪械模型的胶囊体表达枪械占用空间。
- 正常持枪时阻止枪械穿入墙体或场景障碍物。
- 枪口顶墙时立即将枪械绕现有左手挂点抬起，避免角色卡死。
- 抬枪状态仍允许射击，但真实枪械碰撞和世界墙体射线必须阻止枪身与伤害穿墙。
- 所有远程武器统一使用步枪的保守碰撞包络；匕首继续只使用人物主体胶囊体。
- 枪械碰撞只影响墙体和场景障碍，不与僵尸发生物理碰撞。

## 非目标

- 不新增或重制角色骨骼动画。
- 不使用手臂 IK 修正双手位置。
- 不处理枪械与僵尸、掉落物或其他动态实体之间的物理碰撞。
- 除“墙体必须先于墙后目标截断射线”和“转向被拒时使用人物实际朝向”外，不改变既有射程、伤害数值、射速、枪口火焰、曳光弹或辅助瞄准语义。
- 不为匕首增加墙体碰撞或自动收刀行为。

## 已确认的交互规则

### 正常持枪

玩家由两个直接参与 `CharacterBody3D.move_and_slide()` 的形状组成：现有人物胶囊体，以及当前远程武器的枪械胶囊体。为保证所有远程武器切换时墙体限制完全一致，墙体净空控制器只使用一套步枪完整保守包络：

- 胶囊总长 `1.55m`。
- 胶囊半径 `0.12m`。
- 玩家局部中心偏移 `Vector3(0, 1.12, -0.62)`。
- 默认抬枪角 `65°`。

手枪不再使用较短的独立墙体轮廓。统一包络的目标不是精确复刻每把枪，而是让当前及后续新增的任何远程武器都按最长步枪的占用空间提前触发抬枪，并保证贴墙切枪不会改变真实碰撞体积。

Godot `CapsuleShape3D` 的长轴为形状局部 `Y`。`NORMAL` 把该长轴旋转到玩家局部前后轴，中心使用上述玩家局部偏移；`RAISED` 再绕握枪枢轴把长轴向上抬 `65°`。世界 yaw 只由 `Player` 的全局变换继承一次；直属 `WeaponCollision` 的局部变换只包含中心偏移和抬枪俯仰，不得再次写入人物 yaw。用于预测目标朝向的 probe 可以临时包含 `target_yaw - current_yaw`，但该预测变换不能原样提交给真实碰撞体。

### 空间不足与抬枪

墙体空间控制器维护 `NORMAL` 和 `RAISED` 两种状态：

1. `NORMAL` 状态使用水平枪械胶囊参与墙体碰撞。
2. 每个物理帧在人物转向和 `move_and_slide()` 前，`NormalProbe` 使用目标 yaw 和本帧期望位移做扫掠查询。只要统一长度的正常胶囊已经顶墙、期望移动会让枪身进入墙体，或目标朝向的正常姿态受阻，就请求 `RAISED`。
3. 只有目标 `RAISED` 姿态也通过 `RaisedProbe` 验证时，才在同一物理帧提交 `RAISED` 状态、真实胶囊、可见枪械和允许的人物朝向。物理与视觉直接切到 `65°`，不做会让二者短暂失配的抬枪插值，也不等待攻击键释放。
4. 若 `RaisedProbe` 失败，则请求不提交：状态、真实胶囊、可见枪械目标和人物朝向全部保留上一合法值，不能把任何部分旋入墙体或低顶。现有运动碰撞继续阻止玩家向障碍物推进。
5. `RAISED` 状态始终保留真实胶囊碰撞，不能通过关闭枪械体积解决阻挡。
6. `RAISED` 中探测正常姿态时，`NormalProbe` 除本帧期望位移外，再沿目标朝向的局部前方增加 `0.08m` 查询位移；这 `0.08m` 是恢复查询余量，不修改真实胶囊尺寸或中心。
7. 正常姿态连续安全 `0.15s` 后，才在一个物理帧内把真实胶囊和可见枪械直接提交回 `NORMAL`。若等待期间当前 `RAISED` 目标姿态受阻，则保持上一合法姿态和朝向；只有恢复计时完成且完整 `NORMAL` 姿态仍安全时才允许切换。

控制器区分“请求姿态”和“已提交姿态”。射击、真实碰撞、视觉状态和人物朝向只读取已提交结果，不得读取尚未通过 probe 的目标值。

### 移动、转向与脱离

- 正常持枪胶囊接触墙体时，不能让枪身继续进入墙内。
- 玩家后退或向远离墙体的方向侧移始终允许，以保证可以脱离狭窄位置。
- 转向前验证目标朝向；正常姿态不足但抬枪姿态可用时，先进入 `RAISED`，再允许人物继续转向。
- 快速切枪时，由于所有远程武器共享同一碰撞包络，新武器继承当前已提交的 `NORMAL`/`RAISED` 姿态；新网格在显示前直接设置到该姿态，不能先显示穿墙帧，也不能短暂关闭枪械碰撞。
- 从匕首切入远程武器时，先验证 `NORMAL`，再验证 `RAISED`，只有至少一个姿态安全才提交装备并记录首个合法姿态。两者都不安全时拒绝本次切换，继续保留匕首，不能显示、启用或开火一个没有合法初始姿态的枪。
- 目标转向被墙体拒绝时，人物保持上一合法朝向；射击方向同步使用人物实际朝向，不能向尚未成功转到的方向发射。
- 切到匕首、武器卸下或玩家死亡时，关闭枪械胶囊并恢复所有武器网格保存的初始局部变换。

### 射击输入

- `NORMAL` 和 `RAISED` 均允许远程武器按原射速开火；墙体净空系统不设置攻击释放门闩，也不因抬枪调用 `cancel_attack()`。
- 枪口标记继续跟随武器网格，因此抬枪期间枪口火焰、声音和曳光弹从已提交抬枪姿态的枪口位置生成。功能射线仍是水平玩法射线，不沿 `65°` 的视觉枪管向天空发射；曳光弹从视觉枪口收敛到功能射线命中点。
- 人物应用控制器返回的 `accepted_yaw` 后，远程攻击方向必须从人物当前实际前向重新计算，不能继续传递未采纳的 `aim_direction` 或 `target_yaw`。
- 所有远程射线查询必须包含世界第 1 层，并排除玩家自身。若第 1 层墙体位于功能射线起点与目标之间，墙体必须是第一次命中，墙后目标不能受到伤害；本次射击仍正常播放枪口火焰、声音和到墙面的曳光弹。

## 架构与组件

### `WeaponClearanceController`

新增独立的 `Node3D` 控制器，职责限定为：

- 接收当前武器定义和对应视觉挂点。
- 用唯一的步枪包络常量配置玩家直属的枪械 `CollisionShape3D`，不读取每把武器的独立尺寸。
- 使用同尺寸的空间查询判断正常与抬枪姿态是否可用。
- 维护 `NORMAL`、`RAISED` 状态和恢复计时；墙体净空不再拥有攻击释放门闩。
- 保存并恢复每个武器视觉网格的初始局部变换。
- 保存上一合法的已提交姿态、本地碰撞 transform 和人物 yaw；请求失败时原样返回这些值。

控制器不负责读取玩家按键、不执行伤害查询，也不生成枪口反馈。有效远程武器在任一净空姿态下都允许射击；控制器只解析安全姿态和允许采用的人物朝向。

### 玩家场景节点

`Player.tscn` 包含：

- `WeaponCollision`：`CollisionShape3D`，必须是 `Player` 的直接子节点，确保它与人物胶囊共同参与 `CharacterBody3D` 运动求解。
- `WeaponClearanceController`：负责状态与视觉变换。
- `WeaponClearanceController/NormalProbe` 和 `RaisedProbe`：使用与 `WeaponCollision` 相同的统一步枪胶囊资源执行世界第 1 层空间检查。

两个 probe 都使用 `ShapeCast3D`，只查询世界第 1 层、`collide_with_areas = false`，并排除玩家自身 RID。它们在每个物理帧用目标 yaw、目标姿态和本帧期望位移强制刷新查询；检测到正常姿态阻挡的同一物理帧，必须在人物旋转和移动前提交安全的抬枪姿态。探测节点只负责查询，真实阻挡始终由 `WeaponCollision` 完成。玩家目前只碰撞世界第 1 层，僵尸移动体不在该层，因此枪械胶囊不会与僵尸产生物理接触。

### 武器配置

远程武器定义不再拥有可变的单枪墙体尺寸。`WeaponClearanceController` 集中声明唯一常量 `1.55 / 0.12 / Vector3(0, 1.12, -0.62) / 65°`，恢复稳定时间 `0.15s` 和恢复查询余量 `0.08m` 也集中配置在控制器。现有资源中的旧墙体字段应删除，不能继续成为运行时行为来源。匕首等近战装备时控制器关闭枪械碰撞。

### 数据流

1. `EquipmentController` 在显示新武器前请求墙体空间控制器预检。远程到远程切换继承已有合法姿态；近战到远程切换必须先取得合法的 `NORMAL` 或 `RAISED` 初始姿态。预检失败时 `equip_slot()` 返回 `false` 并保留原装备。
2. 预检通过后，墙体空间控制器找到 `WeaponBase.visual_anchor`，保存其初始局部变换，以统一常量配置三个胶囊，并把新网格直接设置到已提交姿态；随后装备层才显示新武器。
3. 人物每个物理帧先提供期望移动和目标 yaw，墙体空间控制器查询并返回 `accepted_yaw` 与已提交姿态。
4. 人物控制器应用 `accepted_yaw`，真实 `WeaponCollision` 只继承这次父节点 yaw，然后调用 `move_and_slide()`。
5. 人物控制器从应用后的实际人物前向生成远程射击方向；装备层继续按原逻辑提交攻击输入，不因 `RAISED` 取消攻击或改写射速。
6. 墙体净空的 probe、状态、物理与视觉姿态提交全部发生在物理帧，不再需要普通 `_process()` 视觉插值。

## 防错行为

- 候选远程武器找不到 `visual_anchor`：拒绝该次装备并输出包含 `weapon_id` 的警告；保留上一装备及其合法碰撞，不得把无合法视觉/碰撞契约的枪显示或启用。若发生在初始装备且没有上一武器，则候选枪保持隐藏和不可攻击，玩家只保留人物主体碰撞。
- 统一常量在开发期由测试断言为有限且合法；运行时不接受武器资源覆盖，因此不存在用错误单枪配置关闭碰撞的降级路径。
- 正常与抬枪姿态都被占用：不强行改变真实形状，不把角色传送或推出墙体，保留当前合法姿态和人物朝向，并让运动碰撞阻止继续靠近；仍允许沿实际朝向射击。
- 从近战首次装备远程武器且两个姿态都被占用：拒绝切换并保留近战。远程到远程切换直接继承统一包络的上一合法姿态，不重新走“禁用碰撞”路径。
- 武器切换、死亡或节点退出场景：恢复保存的局部视觉变换并清理已提交状态；仅当当前不再装备远程武器时关闭枪械胶囊。

## 测试与验收

### 单元测试

- 控制器统一常量为 `1.55m / 0.12m / Vector3(0, 1.12, -0.62) / 65°`，并且全部远程武器定义不再提供覆盖字段。
- 正常姿态顶墙时状态机立即进入 `RAISED`；抬枪目标受阻时不提交非法真实碰撞姿态。
- 正常空间持续恢复不足 `0.15s` 时不放下，达到阈值后才恢复。
- `RAISED` 状态仍允许射击，不设置释放门闩。
- 切到近战、死亡时关闭枪械碰撞并恢复视觉变换；候选远程武器缺少挂点时拒绝装备并保留上一合法状态。

### 场景与物理集成测试

- 玩家场景包含直属 `WeaponCollision` 和墙体空间控制器；`WeaponCollision`、`NormalProbe`、`RaisedProbe` 三个指定形状始终使用统一总长、半径和中心规则。
- 正常姿态靠墙时，在人物主体胶囊尚未接触墙体的位置，通过真实 `move_and_collide()` 或 `move_and_slide()` 证明枪械胶囊先阻止继续前进；后退和远离墙体的侧移仍可脱离。
- 抬枪姿态可用时进入 `RAISED`，玩家可后退、侧移和在窄门中转身，不发生持续重叠或抖动。
- 遍历当前全部远程武器；切换前后 `WeaponCollision`、`NormalProbe`、`RaisedProbe` 都保持 `1.55m / 0.12m`，贴墙切换第一帧继承合法姿态且真实碰撞不中断。
- `NORMAL`、`RAISED` 各执行一组正反例：墙位于功能射线起点和目标之间时，直接射线查询的第一命中为墙、目标生命值不变且射击反馈正常；移除墙后，以同一方向和距离再次射击必须命中并伤害目标。
- 固定人物目标 `yaw = 90°` 后，断言直属 `WeaponCollision` 的世界中心、长轴和首次碰撞点只继承人物 yaw 一次，并通过真实运动求解验证阻挡。
- `RaisedProbe` 在目标方向受阻时，状态、视觉、真实碰撞和人物 yaw 都保持上一合法值；`RAISED + normal_clear + raised_blocked` 的恢复等待期间也不得提交碰撞姿态。
- 制造一个被墙拒绝的非零目标 yaw 后开火，断言射线方向、人物实际前向和已接受 yaw 一致，并且不命中只位于被拒绝方向的目标。
- 从近战切远程且两个姿态都被占用时，切换返回失败、近战保持装备、候选枪保持隐藏且不可攻击；远程互切不会关闭真实碰撞。
- 枪械胶囊不与僵尸的受弹区域或移动体产生物理碰撞。

### 运行时视觉验收

使用 Godot 4.7.1 运行演示场景，至少检查手枪和步枪各一次：正面靠墙、斜向墙角、窄门转身、贴墙切枪、后退恢复和抬枪射击。抬枪必须在顶墙帧直接绕左手现有挂点切到 `65°`，允许步枪右手离开护木；射击反馈必须正常出现，但墙后的目标不得受伤。不允许枪械明显脱离左手、穿墙、闪现到错误位置或在边界连续抖动。

## 完成条件

- 全部新增与回归测试通过。
- Godot 无场景或脚本解析错误。
- 除墙体遮挡和被拒绝转向的射击方向收敛外，无遮挡射击的命中、伤害和武器反馈保持不变。
- 手枪、步枪和匕首切换行为符合本设计。
- 通过 Godot 运行时视觉验收并保存用于评审的截图或短视频证据。
