# 武器胶囊允许僵尸穿透设计

## 背景

玩家根节点是 `CharacterBody3D`，人物主体胶囊和远程武器的 `WeaponCollision` 都直接挂在同一个物理身体下。Godot 对碰撞层和碰撞遮罩的配置属于整个 `PhysicsBody3D`，不能为同一身体下的两个 `CollisionShape3D` 分别指定遮罩。

玩家当前同时碰撞世界层和 `ZombieBlocker` 层。人物主体需要保留这项行为，让僵尸不能穿过玩家身体；但向前伸出的武器胶囊也继承了同一遮罩，使正面僵尸在约一把长枪的距离外就顶住玩家。僵尸模拟仍按中心距离 `1.45m` 才进入攻击状态，因此正面接触时会持续推着玩家移动，却无法靠近到攻击距离。侧面和背面没有武器胶囊提前阻挡，所以攻击正常。

## 目标

- 僵尸可以穿过远程武器的胶囊占用空间。
- 僵尸仍然不能穿过玩家人物主体胶囊。
- 远程武器仍会检测墙体并切换正常、抬枪或收枪姿态，避免枪械穿墙。
- 枪口位置、射线起点和视觉姿态继续使用当前武器胶囊的尺寸与变换数据。
- 不改变僵尸攻击范围、攻击前摇、伤害或追击逻辑。

## 方案

### 武器胶囊退出玩家运动碰撞

`WeaponCollision` 保留为玩家直属的 `CollisionShape3D`，但不再启用为真实物理碰撞形状。它继续保存武器胶囊的尺寸和当前姿态变换，供以下逻辑读取：

- `WeaponClearanceController.get_weapon_muzzle_origin()` 计算枪口端点。
- 正常、抬枪和收枪姿态提交时同步胶囊局部变换。
- 远程武器的功能射线与表现反馈使用当前端点。

控制器不得在绑定远程武器或切换姿态时重新启用 `WeaponCollision`。切换近战、卸下武器、死亡和退出场景时仍保持它禁用。

### 墙体净空继续由查询形状负责

`NormalProbe` 和 `RaisedProbe` 继续使用与武器胶囊相同的尺寸，只查询世界第 1 层。它们仍负责：

- 预测本帧移动和目标朝向下的正常持枪空间。
- 正常姿态受阻时选择抬枪或收枪姿态。
- 空间恢复稳定后回到正常姿态。

因此本次修复只移除武器与动态僵尸之间的真实运动阻挡，不取消墙体净空检测，也不改变视觉抬枪行为。

### 玩家主体碰撞保持不变

玩家根节点继续使用当前碰撞层和遮罩，人物主体胶囊仍与世界层及 `ZombieBlocker` 层发生碰撞。僵尸从正面穿过枪械空间后，会在人物主体胶囊处停止；此时中心距离可以进入现有 `1.45m` 攻击范围。

## 验证

增加聚焦验证，覆盖以下契约：

1. 玩家仍位于玩家层，并继续碰撞世界层和 `ZombieBlocker` 层。
2. 远程武器绑定后 `WeaponCollision` 仍保持禁用。
3. 正常、抬枪和收枪姿态切换不会重新启用 `WeaponCollision`。
4. 武器胶囊的尺寸和姿态仍能用于计算枪口端点。
5. `NormalProbe` 与 `RaisedProbe` 继续只查询世界层。
6. 运行 Godot headless editor import/parse 检查以及相关玩家、碰撞验证。

视觉与交互验收：正面持远程武器站立时，僵尸应穿过枪械前端，在玩家身体前停下并正常播放攻击前摇、造成伤害；侧面与背面行为不应改变。

## 非目标

- 不把武器拆成独立物理身体。
- 不扩大僵尸攻击范围来补偿枪长。
- 不修改确定性模拟、联机协议或帧同步数据。
- 不改变枪械对墙体的净空查询、射线截断或视觉反馈。
