# 玩家头顶通用血条设计

## 目标

新增一个可复用的 3D 血条组件，并只在本轮把它接入玩家头顶。血条始终显示、无数值文字、长度适中；它根据当前血量切换绿色、黄色和红色，且即使玩家被场景物体遮挡也必须可见。

本轮删除原有左上角 `HP 当前值 / 最大值` 文本。僵尸血条及僵尸现有 `HealthLabel` 不在本轮改动，但新组件必须能在未来被僵尸或其他可受伤单位复用。

## 已确认的视觉规则

- 使用极简细条样式：轻量圆角、没有边框、没有刻度、没有数字、没有受伤残影。
- 世界空间基础尺寸为约 `1.1m × 0.10m`；在现有固定跟随相机下呈现约 `100 × 9 px` 的观感。
- 背景为深色半透明圆角条；填充条从左向右显示，左边缘固定，减少血量时右边缘向左收缩。
- 血量比例大于 `60%` 时为绿色；大于或等于 `30%` 且小于或等于 `60%` 时为黄色；低于 `30%` 时为红色。
- 初始同步不播放动画；后续生命值变化在约 `0.20` 秒内平滑过渡。连续更新时从当前可见宽度过渡到最新目标值，并安全替换旧动画。
- 血量归零后填充条收缩到零，背景条继续保留在死亡玩家头顶，直到 Demo 场景重开。
- 血条始终朝向相机、保持水平，不跟随玩家身体转向。
- 血条材质不受场景光照影响，关闭深度检测并安排明确渲染顺序，因此玩家、墙体或道具遮挡角色时血条仍显示在最上层。

## 方案选择

采用“独立 `HealthBar3D` 场景 + 双层 3D 面片”的方案。

不采用 `SubViewport + ProgressBar`：它能复用 2D 控件样式，但对当前简单血条增加了额外节点和渲染成本。

不采用屏幕空间 HUD 投影：它可以保持固定像素尺寸，但依赖相机和 HUD 管理器；未来多个单位接入时还要集中管理投影坐标。

双层 3D 面片的方案将血条保持为单位场景的子节点，组件可独立复用，不需要额外管理器，并且可通过无深度检测实现已确认的穿透显示规则。

## 组件边界

### `HealthBar3D`

新增场景 `scenes/ui/HealthBar3D.tscn` 和脚本 `scripts/ui/health_bar_3d.gd`。

它的节点结构为：

- 根 `Node3D`：保持血条位置与相机朝向。
- `Background`：深色半透明圆角背景面片。
- `Fill`：彩色圆角填充面片。

它只负责可视化，不创建、保存或修改 `Health` 对象。它的公共接口为：

```gdscript
func set_health(current: float, maximum: float, animate: bool = true) -> void
```

接口会将 `current` 限制在 `0.0` 到 `maximum` 范围内，计算填充比例，选择颜色并更新显示。`maximum <= 0.0` 时视为空血条，不能发生除零异常。每个实例必须拥有独立的材质参数，未来多个单位同时调用时不能互相改色或改宽度。

为保持组件可测试，比例计算和颜色选择作为无场景依赖的脚本方法，至少覆盖边界 `0%`、`30%`、`60%`、`100%` 和无效最大血量。

### `PlayerController`

玩家仍由现有 `Health` 管理生命值，`Health.changed(current, maximum)` 仍驱动 `PlayerController.health_changed` 公共信号。

`PlayerController` 同时取得子节点 `HealthBar3D`：

1. `_ready()` 中在生命对象完成初始化后调用 `set_health(current, maximum, false)`，确保满血首次显示没有动画。
2. `_on_health_changed(current, maximum)` 继续发射公共信号，并调用 `set_health(current, maximum, true)`。
3. 没有血条节点时记录一次明确警告但不改变伤害、死亡、武器或移动流程。

玩家场景在根节点下新增 `HealthBar3D` 实例，局部位置为约 `Vector3(0, 2.35, 0)`，使它位于玩家模型头顶。玩家与组件之间只通过 `set_health` 传递数值，组件不反向访问玩家状态。

### `DemoArena`

移除 `HUD/PlayerHealth` 节点和 `_on_player_health_changed()` 对其文本的更新。`DemoArena` 不再为该 HUD 文本连接玩家 `health_changed`，但保留伤害闪红与死亡提示的现有绑定。

不修改僵尸场景、`ZombieTarget` 或其 `HealthLabel`；不新增僵尸血条、通用单位管理器、屏幕投影管理器或新的输入操作。

## 渲染与动画细节

`Background` 和 `Fill` 使用不受光照影响的透明材质与圆角遮罩。填充层比背景层具有更靠前的局部偏移或渲染优先级，避免两个共面面片的闪烁；两层关闭深度检测，确保它们在场景对象前绘制。

根节点采用相机朝向的 billboard 配置，使相机绕玩家移动时血条仍可读。组件只动画填充面片的可见宽度与右边缘位置，不能缩放背景、移动左边缘或修改根节点位置。

当一次新生命更新发生时，若旧 Tween 有效则先停止它。新 Tween 从当前 `Fill` 宽度开始，在 `0.20` 秒内到达新比例；颜色根据最新的真实生命比例立即设置，不等待宽度动画结束。

## 错误与边界

- `maximum <= 0.0`：填充比例固定为 `0.0`，不除零。
- `current < 0.0` 或 `current > maximum`：限制到有效范围后再显示。
- 连续受伤、治疗或脚本化数值更新：始终只保留一个有效的填充动画。
- 场景组件的 `Background`、`Fill` 或材质缺失：输出节点路径相关的警告并安全停止视觉更新；游戏伤害流程持续正常运行。
- 玩家死亡后：不隐藏背景，允许填充条收缩至零；现有 `PLAYER DOWN` 逻辑维持不变。

## 测试与验收

本轮按中等风险的轻量验证执行，只做与此功能直接相关的测试和 Smoke Test，不追求覆盖率。

### 自动测试

- 新增或扩展单元测试，验证比例限制、`maximum <= 0.0`、颜色区间与三个阈值边界。
- 新增场景契约测试，验证玩家场景实例化 `HealthBar3D`，位置为头顶高度，组件没有 Label/数值文字，且背景与填充使用 billboard、透明和关闭深度检测的配置。
- 扩展 Demo 集成测试：初始玩家血条为满血；受到伤害后目标比例为 `0.9`；致命伤害后目标比例为 `0.0`；旧 `HUD/PlayerHealth` 不再存在；现有游戏结束提示仍显示。

### Smoke Test

运行 Godot 无头编辑器导入检查以及针对血条的测试路径；若相关测试没有回归，再运行完整 `./tests/run_tests.sh`。不使用 UI 自动化。

### 人工验收

在 Demo 中受到僵尸攻击，确认：

1. 玩家头顶从启动起一直可见血条，且没有数字文本。
2. 血条长度适中、左边缘稳定、扣血在约 `0.20` 秒内平滑缩短。
3. 血量经过 `60%` 和 `30%` 阈值时依次显示绿色、黄色、红色。
4. 玩家被场景墙体或道具遮挡时，血条仍在画面最上层。
5. 玩家死亡时填充条归零，背景仍在，`PLAYER DOWN` 提示仍正常显示。

## 非目标

- 僵尸或其他单位实际接入头顶血条。
- 修改僵尸 `HealthLabel`、伤害值、治疗机制、死亡动画、武器或 AI。
- 左上角新的图形血条、数字血量、刻度、受伤残影或屏幕投影管理器。
- 动态尺寸随镜头距离调整、血条遮挡隐藏规则或高亮选中状态。
