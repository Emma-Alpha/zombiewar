# 12 格背包系统设计

## 状态

- 状态：设计已获用户确认，待实现
- 日期：2026-08-12
- 范围：地图拾取物、玩家背包、当前装备同步、背包 UI、背包图标资源

## 目标

把当前“拾取后直接显示在 HUD 或当前装备状态中”的资源流改为真正的固定槽位背包。

第一版必须支持：

- 12 个固定背包槽位。
- 武器、弹药、油桶和武器改装件都能进入背包。
- 同类弹药可堆叠。
- 重复拾取武器不增加新槽位，而是增加对应弹药。
- 改装件拾取后立即生效；相同改装件自动累加层数并升级。
- 背包满、弹药满或改装件满级时，地图掉落物不能被错误消耗。
- 当前装备和弹药仍保留在 HUD 中，并与背包同步。
- `Tab` 打开/关闭背包，移动端提供等价的背包按钮。
- 单机和联机都遵循模拟 tick 的确定性拾取流程。

第一版不包含拖拽换位、丢弃、排序、快捷栏扩容、保存读取和商店交互。

## 现有上下文

项目是 Godot 4.7.1 的 2.5D 游戏。地图奖励由 `PickupDefinition` 描述，地图运行时按资源路径建立稳定的 `reward_profile_index`。`SimWorld` 按固定 tick 判断玩家与 `PickupChest` 的领取关系，并通过 `tick_chest_events` 驱动表现层箱子消失和刷新。

当前 `EquipmentController` 管理武器实例和油桶实例，`RangedWeapon` 自己保存弹药，武器改装层数已经由 `SimWorld.player_mod_level` 保存并进入帧哈希。`PickupDefinition.grant_to()` 目前在表现层兑现武器、弹药和油桶奖励。

背包实现必须保留以下架构约束：

- 箱子领取仍由 `SimWorld._resolve_chest_claims()` 决定。
- 波次、箱子刷新、箱子消失和改装生效只能由模拟 tick 驱动。
- 联机不能由表现层直接修改模拟状态。
- 模拟层只保存稳定整数/定长数组，不读取图标、字体、场景等表现资源。
- 背包状态需要进入帧哈希，避免容量和物品内容在不同客户端分叉。
- 拾取物作为阻挡几何时，只有模拟层确认领取成功后才清除阻挡格。

## 方案选择

### 方案一：只拼接现有 HUD

将当前装备、弹药和改装摘要绘制成 12 格面板，但不引入真实槽位状态。

优点是改动小；缺点是无法可靠处理背包满、拾取拒绝和联机一致性。因此不采用。

### 方案二：12 格 `InventoryComponent` 与模拟层容量判定

由背包组件负责槽位和 UI 事件，由 `SimWorld` 保存确定性的槽位内容并判定奖励是否可接收；`EquipmentController` 作为背包与现有武器节点之间的适配器。

优点是能覆盖当前需求，并与现有 tick/帧哈希架构一致；同时不要求第一版引入拖拽和存档。采用此方案。

### 方案三：完整可拖拽物品系统

在方案二基础上增加拖拽换位、丢弃、排序、装备栏和持久化。

扩展性最好，但明显超出当前需求，留作后续版本。

## 玩法规则

### 槽位

- 每个玩家固定 12 格，UI 使用 4×3 网格。
- 初始手枪和匕首各占 1 格。
- 未拥有的武器不占槽位。
- 一种武器只允许存在一个槽位。
- 一种弹药只允许存在一个堆叠槽位。
- 油桶只允许存在一个堆叠槽位。
- 一种改装件只允许存在一个槽位，数量表现为改装等级。

### 武器与弹药

- 首次拾取武器：占用一个槽位，授予武器，并增加拾取定义中的初始弹药数量。
- 重复拾取武器：不新增槽位，只增加该武器弹药；如果武器弹药已满，则不接受拾取。
- 武器是否拥有由背包状态决定，`EquipmentController` 不再拥有独立的拾取真相。
- 当前武器切换仍沿用现有装备切换守卫。
- 弹药消耗后同步减少背包中的对应弹药数量。
- 各武器弹药堆叠上限沿用 `RangedWeaponDefinition.max_ammo`：冲锋枪 360、散弹枪 40、步枪 90；无限弹药武器不创建弹药槽位。

### 油桶

- 油桶占用一个槽位。
- 数量沿用 `PlaceableEquipment.max_count`，当前为 999。
- 放置油桶成功后减少背包数量。
- 放置请求仍遵循现有联机输入/模拟通道，不由 UI 直接扣除。

### 武器改装件

- 第一次拾取某种改装件时占用一个槽位。
- 同类改装件继续写入同一槽位并累加等级。
- 改装效果在模拟层的领取 tick 立即生效。
- 最大等级沿用 `WeaponModTable.MAX_STACKS`。
- 背包显示 `Lv.N`，地面标签继续显示效果说明。
- 达到最大等级后不再接受同类掉落，掉落物保持在地图上等待后续处理。

### 拾取失败

下列情况不会消耗箱子，不清除阻挡格，也不会发出成功拾取事件：

- 新物品没有空槽位。
- 重复武器对应弹药已经达到上限。
- 弹药槽已经达到上限。
- 改装件已经达到最大等级。

失败原因通过事件传给本地 HUD，显示短暂提示，例如“背包已满”“弹药已满”“改装件已满级”。提示是表现层信息，不进入模拟哈希。

## 数据模型

### `PickupDefinition` 扩展

在现有拾取定义上增加背包元数据：

- 背包分类：武器、弹药、油桶、改装件。
- 背包物品 key，区分同一 `item_id` 下的武器和弹药。
- 图标纹理或图标 atlas 区域。
- 最大堆叠数量。
- 关联武器 id 或改装件 id。
- UI 名称和简短说明。

表现字段只用于 UI 和地面外观；模拟层通过运行时注册得到稳定的整数 profile，不读取纹理和场景。

### `InventoryComponent`

建议放置于 `scripts/gameplay/inventory/`，挂在玩家节点或由玩家持有。职责：

- 创建和重置 12 个槽位。
- 根据 profile/key 查找已有槽位。
- 合并堆叠、创建新槽位、判断容量。
- 发出 `inventory_changed`、`slot_changed` 和本地拾取反馈信号。
- 向 `EquipmentController` 提供武器拥有、弹药数量和油桶数量查询。

槽位运行时只保存物品 profile/key 和整数数量；资源定义保持只读，避免修改共享 `.tres`。

### `SimWorld` 状态

为每个模拟玩家增加固定大小的槽位数组，建议使用展平的 `PackedInt32Array`：

- `inventory_slot_profile`：玩家 × 12 的物品 profile，空槽为 -1。
- `inventory_slot_amount`：玩家 × 12 的数量或等级。
- 必要的玩家武器拥有/弹药状态，或从上述槽位稳定推导。

这些数组进入 `SimHasher`。所有 profile 的顺序在地图/装配阶段稳定注册，不能依赖字典遍历顺序或客户端本地数组下标。

## 拾取数据流

```text
玩家量化位置
    ↓
SimWorld._resolve_chest_claims()  （固定 tick）
    ↓
Inventory accept/reject（容量、堆叠、满级）
    ├─ reject → tick_inventory_feedback，本地提示，箱子保持 active
    └─ accept → 更新槽位/弹药/改装，更新帧哈希
                    ↓
              tick_inventory_events
                    ↓
       InventoryComponent / EquipmentController 镜像
                    ↓
                HUD 背包刷新
```

`chest_claimed` 只有在奖励真正接收后产生。接受成功时，箱子的阻挡格清除并进入等待刷新或消耗状态；失败时箱子及阻挡格不变。

射击、放置油桶和切换当前武器都通过现有输入/模拟请求路径更新背包镜像，不能由背包 UI 直接修改数量。

## UI 设计

新增 `InventoryPanel` 与 `InventorySlotView`，建议路径为 `scenes/ui/` 和 `scripts/ui/`。

- `GridContainer.columns = 4`，生成 12 个固定槽位。
- 面板放置在右侧安全区域，打开时覆盖在 HUD 上层。
- 使用锚点、容器和 `canvas_items` 拉伸，不使用只适配 1280×720 的绝对布局。
- 空槽显示暗色金属框。
- 有物品时显示图标和右下角数量/等级。
- 当前装备对应槽位使用高亮边框。
- 悬停或手柄选中显示名称和说明。
- `Tab` 绑定 `toggle_inventory`；`Esc` 关闭。
- 移动端通过 `MobileControls` 或 HUD 背包按钮触发同一动作。
- 打开背包不暂停游戏，不改变模拟 tick。
- 所有中文 Control 显式设置 `NotoSansSC-UI.ttf`，并在新增文本后运行字体覆盖校验。

HUD 仍显示当前武器和当前弹药，但数据源改为 `InventoryComponent`/装备适配器；改装摘要继续从 `SimWorld` 读取，避免 UI 使用过时缓存。

## 图标资源

使用 image-2 生成统一的低多边形末日军事风格图标：

- 手枪、冲锋枪、散弹枪、步枪。
- 四种对应弹药。
- 油桶。
- 十种武器改装件。

图标无文字、无品牌、无装饰性字形，采用高对比色区分分类。生成源按类别制作 atlas，处理为透明 PNG 后保存到 `assets/ui/inventory/`。UI 通过 atlas 区域读取图标，以减少重复资源加载。

生成流程：

1. 用 image-2 生成统一风格的分类图标图集。
2. 使用纯色背景移除流程生成透明边缘。
3. 检查图标是否完整、无文字、水印和明显色键残留。
4. 在 Godot 中导入并完成 headless editor import。
5. 在实际背包面板中检查缩放、对比度和移动端可读性。

## 错误处理与边界

- 未注册的背包 profile：记录明确错误，拒绝接受奖励，不回退到默认物品。
- 缺少图标：使用项目内明确的缺失图标占位，不影响模拟层。
- 资源配置中的 key 重复：地图/资源验证阶段报错。
- 武器、弹药或改装件关联 id 不存在：验证阶段报错。
- 12 格之外的槽位访问：安全返回失败，不修改状态。
- 背包组件尚未初始化：拒绝拾取并输出一次警告，不销毁箱子。
- 玩家死亡：不能领取新的箱子。
- 联机重连/回放：背包数组随历史帧逐 tick 重放，不能在 live tick 直接注入。

## 测试和验证

### 稳定行为测试

- 初始手枪和匕首占用两个槽位。
- 新武器首次拾取占用一个槽位并授予弹药。
- 重复武器拾取不新增槽位，只增加弹药。
- 弹药正确堆叠并受上限限制。
- 油桶拾取和使用正确增减数量。
- 同类改装件自动升级，等级不超过最大值。
- 新物品无空槽时拾取失败且箱子保留。
- 满弹时重复武器/弹药拾取失败且箱子保留。
- 满级改装件拾取失败且箱子保留。
- HUD 与背包在装备切换、射击、放置和拾取后同步。

### 人工检查

不使用 CUA 自动操作。进入 Demo 后人工验证：

1. 按 `Tab` 打开/关闭背包。
2. 依次拾取武器、弹药、油桶和改装件。
3. 检查重复武器、弹药堆叠和改装升级。
4. 填满 12 格后继续拾取，确认掉落物不消失。
5. 射击、放置油桶、换武器，确认背包和 HUD 同步。
6. 在桌面、宽屏和移动端检查安全区与字体显示。
7. 在联机房间中由两名玩家同时接近同一箱子，确认所有客户端结果一致。

## 完成定义

- 运行时不再以 HUD 文本作为拾取资源的唯一承载。
- 所有目标拾取物都能在 12 格背包中看到。
- 背包容量和拾取成功/失败由模拟层确定。
- 背包状态进入帧哈希，联机不会因容量判断分叉。
- 当前装备、弹药、油桶和改装等级与背包一致。
- image-2 图标资源已导入并实际用于背包槽位。
- headless 检查通过，人工验证步骤完成。
