# Demo 场景轴对齐斜俯视设计

## 背景

`DemoArena` 当前使用固定角度的正交跟随相机。相机位于玩家的世界坐标对角线方向，水平偏航为 `45°`，因此世界 X/Z 轴在屏幕中呈斜向排列，地图格线和移动方向带有等距视角的菱形感。

本次调整只改变 Demo 游戏场景的观察方向：保留现有斜俯视表现，但取消水平 `45°` 旋转，使屏幕方向与世界轴对齐。主菜单动态背景及其他场景保持不变。

## 目标

- Demo 游戏内采用轴对齐斜俯视。
- 相机水平偏航为 `0°`，从世界 `+Z` 朝 `-Z` 观察。
- 屏幕右方对应世界 `+X`，屏幕上方对应世界 `-Z`。
- 保留约 `-40.3°` 的俯角、正交尺寸 `18`、现有高度和观察距离。
- 保留相机跟随、平滑移动和射击后坐逻辑。
- 不改变玩家控制、射击、场景物体布局或主菜单背景。

## 非目标

- 不改为垂直正上方视角。
- 不旋转 `DemoArena` 的世界节点或场景内容来抵消相机角度。
- 不新增运行时相机切换或可配置视角系统。
- 不调整主菜单 `MenuBackdrop` 的透视相机和动态摆动。
- 不重排玩家、僵尸、车辆、集装箱或其他关卡物体。

## 设计

### 相机固定变换

只调整 `scenes/camera/FollowCamera.tscn` 中 `Camera3D` 的固定变换：

| 参数 | 当前值 | 目标值 |
| --- | --- | --- |
| 位置 | `(10, 12, 10)` | 约 `(0, 12, 14.142)` |
| 旋转 | `(-40.3°, 45°, 0°)` | `(-40.3°, 0°, 0°)` |
| 投影 | 正交 | 正交，不变 |
| 正交尺寸 | `18` | `18`，不变 |

新的 Z 轴距离约为 `sqrt(10² + 10²) = 14.142`。这样可保留原有相机高度、水平距离和俯角，避免因取消对角方向而产生额外的画面缩放变化。

### 组件边界

- `FollowCamera.tscn` 负责静态观察方向和投影参数。
- `follow_camera.gd` 继续只负责跟随目标、平滑和射击后坐，不需要修改。
- `demo_arena.gd` 继续把 `Camera3D` 注入玩家控制器，不需要修改。
- `player_controller.gd` 和 `player_motion.gd` 继续根据相机基向量计算移动方向，不需要为零偏航增加特例。
- `MenuBackdrop.tscn` 和 `menu_backdrop.gd` 不在改动范围内。

### 数据流

`DemoArena` 启动后仍将 `FollowCamera/Camera3D` 传给玩家控制器。玩家移动输入通过现有相机相对移动算法投影到 XZ 平面。偏航变为 `0°` 后，算法自然产生以下映射：

- `W` → 世界 `-Z` → 屏幕上方
- `S` → 世界 `+Z` → 屏幕下方
- `A` → 世界 `-X` → 屏幕左方
- `D` → 世界 `+X` → 屏幕右方

射击后坐继续接收世界空间的射击方向并偏移跟随根节点，因此不依赖相机偏航，无需调整。

## 错误处理

本次没有新增运行时输入、资源加载或状态分支，因此没有新增错误处理路径。相机方向属于静态场景契约；若参数将来被意外修改，应由集成测试发现，而不是增加运行时修正逻辑。

## 测试策略

### 自动化测试

扩展 Demo 场景集成测试，验证：

- `Camera3D` 仍使用正交投影。
- 正交尺寸仍为 `18`。
- 相机水平偏航约为 `0°`。
- 相机俯角约为 `-40.3°`。
- 相机在 XZ 平面上的右方向约为世界 `+X`。
- 相机在 XZ 平面上的前方向约为世界 `-Z`。

现有通用相机相对移动测试继续保留任意相机基向量的覆盖，不将底层算法限制为零偏航。

### 手动验收

- 从主菜单进入 Demo 场景。
- 确认画面仍为斜俯视，而不是垂直俯视。
- 确认地图不再以 `45°` 菱形方向显示。
- 确认 W/S 与屏幕上/下对应，A/D 与屏幕左/右对应。
- 确认初始玩家、主要僵尸和场景物体没有因新观察方向而明显被裁切。
- 确认相机跟随、平滑和射击后坐表现仍正常。
- 返回主菜单，确认菜单背景构图和动态摆动没有变化。

## 验收标准

1. 只有 Demo 游戏内跟随相机的固定变换发生改变。
2. Demo 相机偏航为 `0°`，俯角约为 `-40.3°`，正交尺寸为 `18`。
3. 相机位置约为 `(0, 12, 14.142)`，保留原有高度和水平距离。
4. WASD 在 Demo 内与屏幕上下左右一致。
5. 玩家控制、战斗、相机跟随和平滑逻辑无需新增分支且行为正常。
6. 主菜单背景和其他场景不发生变化。
7. 自动化测试全部通过，手动视觉验收通过。
