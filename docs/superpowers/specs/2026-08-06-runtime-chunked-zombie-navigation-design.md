# 僵尸运行时分区导航设计

## 目标

为现有僵尸接入 Godot 3D 导航，让追击和随机游荡都能绕过 DemoArena 中的车辆、集装箱、边界等静态障碍物，不再只按目标直线移动并持续撞墙。

本次同时建立可扩展的场景级导航管理结构，为后续随机地图、建筑破坏和分块世界提供区块注册、注销、标脏和异步重烘焙入口。当前只交付单张 DemoArena 地图和一个导航区块，不实现无限地图、动态区块加载或建筑破坏系统。

## 已确认范围

- 僵尸追击玩家和随机游荡都使用导航路径。
- 不启用 `NavigationAgent3D` avoidance；本次不解决僵尸之间的拥堵或重叠。
- DemoArena 使用运行时后台异步烘焙，不依赖编辑器预烘焙资源。
- 初始波次立即生成，不等待导航就绪。
- 首次导航尚未就绪时，僵尸短暂沿用现有直线移动。
- 导航就绪后，如果目标不可达，僵尸不得退回直线撞墙。
- 玩家与僵尸之间存在世界障碍时，即使直线距离进入攻击范围，僵尸也不得隔着障碍攻击。
- 未来建筑破坏只预留导航更新协议，不实现建筑生命、破碎表现或破坏触发逻辑。

## 方案选择

采用“场景级导航管理器 + 可注册导航区块”。

不把导航烘焙直接堆入 `DemoArena`，避免未来扩展多个区块时重构关卡脚本；也不使用 Autoload 全局服务，因为 Godot 导航地图属于当前 `World3D`，全局服务会增加场景切换、资源释放和测试隔离成本。

导航区块是独立注册和烘焙的生命周期单元，不是独立导航地图。当前世界内的所有区块加入同一个 Godot 导航地图，使未来相邻区块能够连续寻路。

## 总体架构

### `NavigationWorldManager`

在 `DemoArena/World` 下增加场景级导航管理器。它只管理当前 `World3D` 内的导航区块，不参与僵尸状态机、寻路查询或角色移动。

管理器负责：

- 注册和注销导航区块。
- 维护区块状态和可用导航数据状态。
- 标记区块需要更新。
- 请求单个区块异步重烘焙。
- 合并同一区块的重复请求，避免并发烘焙。
- 发出开始烘焙、就绪和失败事件。
- 忽略已注销区块或过期任务的回调。

### `NavigationChunk3D`

每个区块拥有唯一 `chunk_id`、烘焙 AABB、一个 `NavigationRegion3D` 和运行时创建的 `NavigationMesh`。区块负责收集导航源、执行烘焙并向管理器报告结果。

DemoArena 当前只注册一个 `demo_arena` 区块，覆盖整张 44×34 米竞技场。后续随机地图可以创建更多区块并注册到同一个管理器，但本次不实现区块生成器或加载器。

### 导航烘焙来源

烘焙只解析加入导航源分组的简化静态碰撞体，并使用区块 AABB 过滤局部来源：

- 地面碰撞体提供可行走表面。
- 四面边界提供地图边界。
- 车辆和两个集装箱碰撞体提供不可穿越障碍。
- GLTF 视觉模型不加入导航源，不参与烘焙。

`NavigationMesh` 的 agent 尺寸按现有僵尸半径 0.5 米、高度 1.9 米配置，并为障碍物留出少量额外水平间隙。DemoArena 是单层平地，不新增跳跃连接、楼梯连接或 off-mesh link。

## 公开导航管理接口

管理器提供以下概念接口；实现时使用符合现有 GDScript 风格的强类型签名：

- `register_chunk(chunk)`：注册区块并启动首次异步烘焙。
- `unregister_chunk(chunk_id)`：注销区块并使未完成结果失效。
- `mark_chunk_dirty(chunk_id)`：标记区块导航来源发生变化。
- `request_rebake(chunk_id)`：显式请求一次异步重烘焙。
- `get_chunk_state(chunk_id)`：查询烘焙状态、是否存在可用网格以及网格是否 stale。

未来建筑破坏系统的接入顺序固定为：先改变或移除静态碰撞体，再调用对应区块的 `mark_chunk_dirty()`。本次只保证该调用入口和重烘焙生命周期可用。

## 烘焙生命周期与请求合并

区块至少维护 `UNBAKED`、`BAKING`、`READY` 和 `FAILED` 烘焙状态，并独立记录是否已有可用导航数据、是否 stale，以及当前任务版本号。

生命周期规则如下：

1. 区块注册后立即请求首次后台异步烘焙，不阻塞 DemoArena 或波次生成。
2. 同一帧内的多个标脏或重烘焙请求合并为一个任务。
3. 区块正在烘焙时再次标脏，不启动并发任务；当前任务完成后最多补做一次烘焙。
4. 每次任务持有递增版本号。区块注销或出现更新任务后，过期回调不得覆盖当前状态。
5. 首次烘焙成功后，区块进入 `READY` 并向导航地图提交结果。
6. 重烘焙期间旧网格继续服务，完成后替换为新结果。
7. 重烘焙失败时保留旧网格，记录 stale 和错误信息并发出失败事件，不自动无限重试。
8. 首次烘焙失败时没有可用网格，但不阻止关卡、玩家和波次运行。

## 僵尸导航行为

### 导航组件

`ZombieTarget` 场景增加一个 `NavigationAgent3D` 子节点，使用当前 `World3D` 的默认导航地图并关闭 avoidance。agent 只提供路径点，实际速度、重力和碰撞移动仍由 `ZombieTarget` 控制。

### 逻辑目标与路径目标

- `WANDER`：逻辑目标是现有 `wander_target`。
- `AWARE_APPROACH`：逻辑目标是玩家当前位置。
- `ATTACK`：停止平面移动并沿用现有攻击周期。

僵尸只在逻辑目标改变，或追击中的玩家位置移动超过小阈值时更新 agent 的目标位置，避免没有意义地每帧触发完整重规划。每个物理帧从 agent 读取下一个路径位置，并用该路径方向替换现有直线方向。

现有加速度、减速、重力、击退、血迹、动画、感知范围、攻击冷却和难度速度保持不变。导航不接管 `move_and_slide()`。

### 首次导航降级

在导航地图尚未完成首次同步时，追击和游荡短暂沿用当前直线方向。地图出现有效导航迭代后自动切换为路径方向，不要求 DemoArena 或波次系统显式等待。

该直线降级只适用于首次导航不可用阶段。导航已经可用后，路径失败或目标不可达不得再次使用直线降级。

### 不可达与到达处理

- 追击目标不可达时，僵尸沿路径走到最近可达位置后停止，不持续撞击障碍物。
- 游荡目标不可达或到达最近可达点时，进入现有游荡暂停流程，随后重新选择目标。
- 路径方向用于朝向和移动；最终减速仍参考现有抵达逻辑，保持当前移动手感。

### 隔障碍攻击

进入或维持攻击状态需要同时满足：

1. 玩家存活。
2. 玩家直线距离不超过 `attack_range`。
3. 僵尸与玩家之间的世界障碍检测无遮挡。

障碍检测只查询世界碰撞层，不把其他僵尸或命中区域视为遮挡物。距离足够但被车辆、集装箱或墙体阻挡时，僵尸保持追击状态并继续沿导航路径寻找可达方向。

## DemoArena 集成

- 在 `World` 下增加场景级导航管理器和 `demo_arena` 导航区块。
- 地面、边界、车辆和集装箱的 `StaticBody3D` 加入导航源分组。
- 初始波次逻辑不等待导航信号，继续在 `_ready()` 中立即生成。
- 动态加入 `World/Targets` 的僵尸沿用现有依赖绑定，并自动使用自身 `NavigationAgent3D`。
- 首次烘焙失败时，通过 `push_warning()` 报告，并可复用现有 `WaveStatus` 区域短暂显示导航错误；不新增完整导航调试面板。

## 错误与边界处理

- 重复 `chunk_id`：拒绝后注册的区块并报告警告。
- 无效烘焙 AABB、缺少导航区域或没有可解析碰撞体：标记首次烘焙失败，不使关卡加载失败。
- 烘焙期间注销区块：使任务版本失效，完成回调不得访问或恢复已移除区块。
- 重烘焙失败：旧导航继续使用，区块标为 stale，等待外部再次请求。
- 玩家位置落在网格外：agent 以最近可达位置作为路径终点；僵尸不会退回直线撞墙。
- 同一区块的连续破坏事件：通过标脏和补烘焙规则合并，不并发启动多个后台任务。
- 导航路径不能解决角色物理卡住时，不在本次增加局部 avoidance、推挤、卡住检测或传送恢复。

## 测试策略

本功能属于中等风险的游戏行为和异步生命周期改动，测试聚焦核心路径，不改造整个自定义测试框架。

### 单元测试

- 区块注册、注销和重复 ID。
- 首次烘焙、标脏、请求合并和烘焙期间再次标脏。
- 任务版本过期后不提交结果。
- 重烘焙失败时保留旧网格并标为 stale。
- 首次导航未就绪时使用直线降级。
- 导航就绪后使用下一路径点。
- 导航就绪后的不可达目标不使用直线降级。
- 游荡路径完成或不可达后进入暂停并重新选点。

### 集成与场景契约测试

- DemoArena 存在导航管理器和 `demo_arena` 区块。
- 地面、边界、车辆和集装箱碰撞体属于导航源。
- GLTF 视觉节点不属于导航源。
- `ZombieTarget` 拥有 `NavigationAgent3D`，且 avoidance 关闭。
- 测试配置使用同步烘焙验证 DemoArena 简化碰撞体能够生成非空导航网格；生产默认仍为后台异步烘焙。
- 隔着世界碰撞体时，攻击可达性检查返回阻挡。

### 自动验证命令

- `/Applications/Godot.app/Contents/MacOS/Godot --headless --editor --path . --quit`
- `./tests/run_tests.sh`

### 人工验收

1. 从主菜单进入 DemoArena，确认初始波次立即生成。
2. 玩家分别移动到车辆和两个集装箱背面，确认追击僵尸绕过障碍到达玩家，不持续顶墙。
3. 玩家贴近障碍物另一侧，确认僵尸不会隔着碰撞体攻击。
4. 观察游荡僵尸遇到障碍时沿路径绕行。
5. 连续追加波次至 24 只，确认没有明显卡顿、并发烘焙或导航报错。
6. 确认后台首次烘焙完成后，已经生成的僵尸自动从直线降级切换到路径移动。

## 项目规范更新

`AGENTS.md` 增加“3D 运行时导航”规则，要求后续开发遵守场景级管理器、共享导航地图、运行时异步烘焙、简化碰撞源、旧网格保留、请求合并、碰撞变化标脏和 avoidance 默认关闭等约定。

## 非目标

- 无限地图或无限地形生成。
- 动态区块加载、卸载或玩家周边流式管理。
- 建筑生命、破坏、碎裂、掉落或视觉效果。
- 导航区块生成器或随机地图生成器。
- 僵尸间局部 avoidance、拥挤疏散或队列行为。
- 卡住检测、自动传送或强制脱困。
- 多层楼、楼梯、跳跃链接或 off-mesh link。
- 导航调试 UI、性能分析面板或烘焙进度条。
