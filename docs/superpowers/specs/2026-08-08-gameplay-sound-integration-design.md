# 游戏音效接入设计

## 目标

将 `docs/sounds_975 2/` 中用途明确、且当前游戏已有对应触发点的音效接入 Godot 玩法。接入应增强枪械、命中、拾取、放置、爆炸、生物反馈、结算和菜单反馈，同时避免在运行时重复加载音频或因高频触发持续分配节点。

不接入用途不明的 `sound_174`、`sound_175`、`sound_184`、`sound_192`、`sound_193`，也不为当前尚不存在的火箭、地雷、手雷、霰弹枪等玩法提前建设触发逻辑。

## 素材整理与映射

用途明确且当前可用的素材复制到 `assets/sfx/boxhead/`，使用语义化文件名保存；原始 `docs/` 目录继续作为来源和用途记录，不作为运行时资源路径。

## 架构

采用“事件就近播放 + 场景级高频播放器池”，不增加 Autoload。

- 长生命周期对象直接拥有 `AudioStreamPlayer3D` 或 `AudioStreamPlayer`：玩家、僵尸、枪械、爆炸效果和菜单在自身已有行为发生时播放。
- `DemoArena` 持有一个有容量上限的 3D 单次音效播放器池，服务于墙面命中、拾取、油桶放置等声音源可能立即消失的事件。池满时优先复用最早的播放器，避免无上限创建节点。
- 高频播放调用只传入已加载的 `AudioStream`、世界坐标和少量播放参数，不在射击、受击或物理回调内执行 `load()`。
- 音频资源通过场景 `ext_resource`、脚本常量 `preload()` 或预先配置的资源数组引用。Godot 以资源路径缓存并共享音频数据，多只僵尸只增加播放器状态，不复制 MP3 数据。

## 事件行为

### 枪械与命中

- 手枪和自动步枪替换当前共用的金属命中占位声，分别使用手枪与 UZI 素材。
- 保留轻微随机音高，降低连续射击的机械重复感。
- 只有射线撞到非伤害目标的世界障碍时才播放墙面命中声；命中僵尸时由僵尸受击声负责反馈，避免两个反馈叠加。
- 墙面命中从三个短音效中随机选择，并通过场景级播放器池播放。

### 拾取与放置

- `PickupChest` 仅在奖励成功发放后请求拾取声；拾取失败不播放。
- 油桶仅在 `request_place_item()` 成功后播放放置声；库存不足、位置无效或服务不可用时不播放。
- 两类声音均通过场景级播放器池播放，因此源节点可以立即隐藏、释放或切换状态，不会截断音频。

### 僵尸

- 有效受击时播放受击声，并设置短冷却，防止自动武器在同一帧或极短时间内造成刺耳叠音。
- 攻击动画实际开始时播放攻击声。
- 每只存活僵尸使用随机初始延迟和随机间隔尝试播放呻吟；间隔应足够稀疏，并限制同时播放概率，避免大量僵尸形成持续噪声。
- 死亡时停止呻吟和攻击声，播放倒地声；死亡音效所需时长纳入释放等待，避免 `queue_free()` 提前截断。

### 玩家与对局

- 玩家死亡时从两种惨叫中随机选择，同时播放倒地声；玩家对象不会立刻释放，因此声音可以正常结束。
- `DemoArena` 仅在本地队伍首次进入全员倒地状态时播放一次结束提示，重启等待期间不重复播放。

### 菜单

- 菜单选择、确认和返回仍保持原有触发语义，但统一使用来源素材的短点击声。
- 保留“焦点移动时若仍在播放则不重复启动”的现有保护，避免快速导航形成削波或噪声。

## 加载与运行时性能

- 当前选用素材总容量很小，随对应场景预引用；不在进入游戏后逐个从磁盘同步加载。
- 不为每次枪击、碰撞或拾取重新读取、复制或解码一份资源引用。
- 高频世界命中使用固定容量池；低频且有固定宿主的声音复用宿主播放器。
- 僵尸呻吟不使用每帧随机判断，而使用下一次播放时间或计时器，避免随僵尸数量线性增加无意义随机调用。
- 不在 `CombatFxPrewarmer` 中播放音频；渲染预热仍保持静音，符合战斗特效预热约束。
- 首次导入由 Godot 编辑器完成。若导出平台实测 MP3 解码出现明显尖峰，再以相同调用接口将短促高频音效转换为更适合目标平台的格式；本次不预先引入无证据的格式转换。

## 容错

- 音频节点、场景级播放器池或音频资源缺失时，玩法逻辑仍继续执行，只跳过声音并在适当位置发出一次可定位的警告。
- 播放器池容量耗尽不会阻塞攻击、拾取或放置逻辑。
- 音效不得改变伤害、弹药、散布、掉落、导航或输入状态。

## 验证

本改动属于表现层接线，仓库没有持久自动测试套件。按项目约定不新增低价值音频自动测试，采用以下验证：

1. 运行 Godot headless editor 导入检查，确认 MP3、场景和脚本均可解析。
2. 静态检查所有运行时音频路径均位于 `assets/sfx/`，热路径中没有 `load()`。
3. 游戏内检查手枪、自动步枪、墙面命中、僵尸受击/攻击/呻吟/死亡、玩家死亡、拾取、油桶放置与爆炸、全队倒地和菜单按钮。
4. 生成高密度僵尸并连续使用自动步枪，确认没有明显首次播放卡顿、持续节点增长或呻吟声过度拥挤。
5. 确认拾取失败、放置失败、重复结算和渲染预热不会误播声音。
