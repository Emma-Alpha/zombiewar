# Map 关卡编辑器插件设计

## 1. 背景与目标

项目已经采用数据驱动地图运行时：`GameplayArena` 是通用宿主，地图入口场景绑定
`MapDefinition`，`GameMapRuntime` 加载地图内容场景并将网格、阻挡物、波次、补给和
掉落数据装配到 `SimWorld`。

目前地图内容和 `MapDefinition` 主要依赖手工编辑 `.tscn` 与 `.tres`。本功能为开发团队
提供一个 Godot 编辑器插件，以更快地创建和修改完整关卡，同时继续沿用现有运行时资源
和确定性模拟架构。

首版目标：

- 从标准模板快速新建地图。
- 打开并编辑采用新标记协议的已有地图。
- 通过审核过的预制件素材库摆放地图物件。
- 在 3D 视口中编辑玩家出生点、僵尸出生点和固定补给点。
- 在插件面板中编辑现有波次、掉落和地图参数。
- 为单人游戏和本地多人游戏提供共享地图选择流程。
- 联网多人继续固定使用 Demo 地图，不扩展在线协议。

首版强调快速直接编辑，不提供草稿、发布、地图过滤或面向地图作者的完整校验工作流。

## 2. 核心决策

### 2.1 直接编辑运行时资源

插件直接编辑游戏实际使用的资源：

```text
<MapName>Map.tscn
    └── 绑定 MapDefinition.tres
              └── 引用 <MapName>MapContent.tscn
```

不引入独立编辑源、生成产物或发布编译器。保存后，游戏下一次启动该地图时立即读取最新
内容。

### 2.2 保留现有三层地图结构

每张地图由以下文件组成：

- 地图入口场景：继承或实例化通用 `GameplayArena`，只负责绑定 `MapDefinition`。
- 地图内容场景：包含环境、地面、边界、预制件实例和可视化玩法标记。
- `MapDefinition`：包含运行时网格、相机、波次、掉落和同步后的空间数据。

插件不改变 `GameplayArena -> GameMapRuntime -> SimWorld` 的运行时装配关系。

### 2.3 平面地图与异形可行走区域

首版只支持 XZ 平面矩形网格，不支持坡道、多层或高低差寻路。地图作者可在矩形网格内用
围墙、车辆和其他阻挡物围出异形可行走区域。

所有地图物件和玩法标记的 XZ 坐标强制吸附网格。物件可以绕 Y 轴任意角度旋转。旋转后
的阻挡占格继续使用碰撞体的世界轴 AABB，与现有 `GameMapRuntime` 计算方式一致；因此斜放
物件可能占用包围盒边角中的额外格子。

## 3. 插件界面

插件位于 `addons/map_editor/`，启用后提供一个面向地图制作的主工作区。采用三栏综合布局：

```text
┌────────────────┬──────────────────────────┬────────────────┐
│ 预制件素材库   │ Godot 3D 地图视口       │ 地图检查器     │
│ 搜索、分类     │ 摆放、移动、旋转、网格 │ 选中项与参数   │
├────────────────┴──────────────────────────┴────────────────┤
│ 地图参数 | 波次 | 掉落 | 地图目录                         │
└────────────────────────────────────────────────────────────┘
```

### 3.1 左侧：预制件素材库

- 从 `PrefabCatalog.tres` 读取审核过的预制件。
- 支持分类和文本搜索。
- 显示手工指定的缩略图、名称和类型。
- 点击或拖放条目可在当前地图中创建关联场景实例。
- 不支持从项目 FileSystem 任意拖入场景或模型。

### 3.2 中间：Godot 3D 视口

- 使用 Godot 原生 3D 场景编辑能力选择、移动和旋转节点。
- 插件在视口中叠加地图网格、地图范围和玩法标记 Gizmo。
- XZ 移动结果始终回写为最近的网格坐标。
- 旋转只修改 Y 轴，但角度不量化。
- 选中阻挡预制件时显示旋转后世界轴 AABB 的占格预览。

### 3.3 右侧：地图检查器

- 显示当前地图基本信息和选中物件的开放参数。
- 预制件实例保持与原场景关联。
- 默认只允许修改位置、Y 轴旋转和预制件明确导出的参数。
- 不提供“解包为本地节点”，避免地图作者意外修改预制件内部碰撞与分组。

### 3.4 底部：玩法数据

- 地图参数：显示名称、地图范围、格子尺寸、相机边界、感知距离、波间隔、结束模式和最大
  活跃僵尸数。
- 波次：编辑现有顺序波次、僵尸类型、数量和刷新间隔。
- 掉落：编辑现有僵尸死亡掉落组、触发概率、权重、奖励和数量。
- 地图目录：编辑当前地图在 `MapCatalog.tres` 中的名称、简介、封面和排序。

首版不增加指定出生点的波次、击杀或区域触发器，也不扩展现有死亡事件能力。

## 4. 插件组件

### 4.1 `MapEditorPlugin`

Godot `EditorPlugin` 入口，负责：

- 注册和移除 Dock、Gizmo 与标记节点类型。
- 识别当前打开的地图内容场景。
- 协调新建、打开、保存和 Catalog 更新。
- 在插件界面显示文件操作错误。

### 4.2 `MapEditorDock`

承载预制件库、地图检查器和底部数据页。Dock 只修改当前地图场景和当前
`MapDefinition`，不承担运行时地图装配。

### 4.3 `MapMarkerGizmoPlugin`

为玩法标记绘制编辑器可见的颜色、图标、半径和方向提示。标记节点本身不需要可渲染网格，
因此游戏运行时不会显示这些辅助图形。

### 4.4 `MapTemplateBuilder`

从标准模板创建地图目录和三份地图资源。创建前检查目标路径是否已经存在；发现重名时停止，
不覆盖已有文件。

### 4.5 `MapDefinitionSynchronizer`

将内容场景中的玩法标记转换成 `MapDefinition` 空间数组。同步器只负责结构转换和稳定排序，
不实现整图合法性、可达性或波次校验。

## 5. 场景标记协议

采用新协议的地图内容场景包含以下固定分组：

```text
<MapName>MapContent
├── Environment
├── Ground
├── Boundaries
├── Props
└── MapMarkers
    ├── PlayerSpawns
    ├── ZombieSpawns
    └── FixedItemSpawns
```

玩法标记是保存在 `Content.tscn` 中的轻量 `Node3D`：

- `MapPlayerSpawnMarker`
- `MapZombieSpawnMarker`
- `MapFixedItemSpawnMarker`

标记只提供编辑数据和 Gizmo 所需属性，不包含计时器、随机数、物理触发或运行时玩法逻辑。

### 5.1 玩家出生标记

属性：

- 稳定 ID。
- 玩家槽位或排序序号。
- 3D 位置。

保存时生成 `MapDefinition.player_spawn_positions`。

### 5.2 僵尸出生标记

属性：

- `spawn_id`。
- 位置。
- 出生半径。
- 最小间距。

保存时生成 `MapDefinition.spawn_points`。

### 5.3 固定补给标记

属性：

- `spawn_id`。
- `PickupDefinition`。
- 数量。
- 重生延迟 tick。
- 位置。

保存时生成 `MapDefinition.fixed_item_spawns`。

标记 ID 用于稳定排序和编辑识别。同步输出不依赖场景树的临时插入顺序。

## 6. Catalog 数据结构

### 6.1 `PrefabCatalog.tres`

`PrefabCatalog` 保存 `PrefabCatalogEntry` 数组。每个条目包含：

- 唯一 `prefab_id`。
- 显示名称。
- 分类和搜索标签。
- `PackedScene`。
- 手工指定的缩略图资源。
- 编辑器提示类型，例如装饰、障碍或爆炸桶。

Catalog 不重复声明运行时阻挡属性。阻挡来源仍是预制件场景中的碰撞体和
`place_item_obstacle` 分组；爆炸桶继续由现有 `ExplosiveBarrel` 场景和
`GameMapRuntime` 的特殊收集逻辑处理。

### 6.2 `MapCatalog.tres`

`MapCatalog` 保存 `MapCatalogEntry` 数组。每个条目包含：

- `map_id`。
- 地图入口 `PackedScene`。
- 显示名称。
- 简介。
- 手工指定的封面图片资源。
- 显示顺序。

Catalog 是单人和本地多人地图选择界面的唯一列表来源。首版不保存草稿、发布或有效状态，
也不根据地图内容过滤条目。

## 7. 新建地图流程

1. 地图作者在 Dock 中点击“新建地图”。
2. 输入地图 ID、显示名称、网格宽高和单格尺寸。
3. 插件确认以下目标文件均不存在：

```text
scenes/maps/<map_id>/<PascalName>Map.tscn
scenes/maps/<map_id>/<PascalName>MapContent.tscn
resources/maps/<map_id>/<map_id>_map.tres
```

4. 从标准模板创建地面、四面边界、环境、默认玩家出生点、四个僵尸出生点和一组基础波次。
5. 入口场景绑定新 `MapDefinition`，后者引用新内容场景。
6. 插件将新地图加入 `MapCatalog.tres`。
7. 打开新内容场景，进入正常编辑流程。

简介和封面允许稍后手工补充。插件不因它们为空而隐藏地图。

## 8. 编辑与保存流程

### 8.1 预制件摆放

1. 地图作者从 `PrefabCatalog` 选择预制件。
2. 插件在视口落点实例化关联场景。
3. XZ 坐标立即吸附到当前 `MapDefinition` 网格；预制件自己的 Y 高度保持不变。
4. 节点加入内容场景的 `Props` 或约定容器。
5. 后续移动继续强制网格吸附，Y 轴旋转保持任意角度。

### 8.2 地图范围调整

修改网格宽高或单格尺寸时，插件同步更新标准模板生成的地面和边界尺寸。已有物件不会自动
重新排布或删除；快速编辑模式允许作者自行处理范围变化后的内容。

### 8.3 保存同步

保存地图时按以下顺序执行：

1. 将所有受管物件和玩法标记的 XZ 位置重新吸附到网格。
2. 按稳定 ID 收集玩家出生标记、僵尸出生标记和固定补给标记。
3. 重建 `MapDefinition.player_spawn_positions`、`spawn_points` 和
   `fixed_item_spawns`。
4. 保存当前 `Content.tscn`。
5. 保存 `MapDefinition.tres`。
6. 如果目录信息改变，保存 `MapCatalog.tres`。

波次、掉落和非空间地图参数由 Dock 直接修改 `MapDefinition` 及其子资源。

插件不在保存时调用额外地图校验，也不阻止保存或启动。运行时仍保留现有
`MapDefinition.validate_configuration()` 和 `GameMapRuntime.load()` 行为。

## 9. 游戏地图选择流程

新增共享地图选择场景：

```text
主菜单
├── 单人游戏
│   └── 地图选择 → 配置单人会话 → 启动所选地图
├── 本地多人
│   └── 地图选择 → 设备加入大厅 → 启动所选地图
└── 联网多人
    └── 在线大厅 → 固定启动 DemoMap.tscn
```

地图选择界面从 `MapCatalog.tres` 读取全部条目，展示手工封面、地图名称和简介，并提供选择、
确认和返回操作。

所选地图入口路径保存在 `GameSession`：

- 单人确认后配置单人会话并启动所选入口场景。
- 本地多人确认后先进入现有设备加入大厅；P1 开始游戏时读取已选入口场景。
- 退出或清理会话时清除选择，避免旧状态泄漏到下一次开局。
- 联网大厅不读取该选择，继续使用固定 Demo 路径。

`MapCatalog` 中的每一项都会显示。若入口场景资源丢失，界面保留该项并显示资源缺失；用户
尝试启动时展示加载失败信息，不自动过滤或修复目录。

## 10. 错误处理

首版只处理直接文件操作错误：

- 新建地图路径重名：停止创建且不覆盖。
- 模板文件创建或保存失败：在 Dock 显示目标路径和 Godot 错误码。
- Catalog 保存失败：地图资源保留，提示目录登记未保存。
- 地图入口资源丢失：地图选择界面显示缺失并在启动时报告错误。

插件不预检以下问题：

- 出生点是否在网格内或被阻挡。
- 异形区域是否可达。
- 碰撞体或阻挡分组是否完整。
- 波次、掉落或资源引用是否符合运行时配置要求。
- 地图是否适用于本地多人或联网多人。

这些问题由地图作者、现有运行时错误和工程验证发现。

## 11. Demo 地图处理

当前 Demo 地图直接重建为新场景标记协议，不提供旧地图自动迁移工具。重建必须保持以下
玩法结果基本不变：

- 地图布局和主要碰撞位置。
- 网格范围和相机边界。
- 玩家与僵尸出生位置。
- 固定补给位置、内容、数量和重生间隔。
- 波次数量、僵尸数量和波间隔。
- 僵尸死亡掉落概率、权重和奖励。
- 爆炸桶及其他运行时阻挡行为。

Demo 同时作为 `PrefabCatalog`、`MapCatalog` 和新标记协议的基准示例。

## 12. 验证策略

插件本身不向地图作者提供校验功能，但实现仍需进行工程级验证：

- Godot 无头 editor import，确认插件、资源脚本和场景可以解析。
- 加载并实例化插件生成的最小地图，确认入口、内容和 `MapDefinition` 引用正确。
- 保存同步的聚焦验证，确认三类标记按稳定 ID 写入正确数组。
- 网格吸附的聚焦验证，确认负坐标、非单位格子和重复保存结果稳定。
- 预制件实例验证，确认保持场景关联且旋转后阻挡仍走现有世界轴 AABB 路径。
- 地图选择流程验证，确认单人和本地多人启动选中地图，联网仍固定 Demo。
- 运行现有 Demo 地图数据驱动、流场、碰撞、确定性、补给和爆炸桶相关验证，确认 Demo
  重建未改变既有玩法合同。

视觉和交互效果无法通过无头检查完全覆盖时，由用户按简短步骤在 Godot 编辑器和游戏中
手工检查，不使用 CUA 自动操作编辑器。

## 13. 首版范围外

- 草稿、发布、版本管理和自动生成运行时产物。
- 地图目录有效性过滤。
- 插件内整图校验、可达性检查或波次预检。
- 专用撤销/重做；依赖场景保存和版本控制。
- 旧格式地图迁移器。
- 高低差、多层或异步寻路。
- 从 FileSystem 任意拖入未审核资源。
- 预制件实例解包和任意内部节点修改。
- 波次指定出生点、击杀触发、区域触发和时间触发扩展。
- 在线地图选择、服务器地图同步和协议版本扩展。
- 编辑器内嵌试玩模式。
- 自动生成地图封面。
