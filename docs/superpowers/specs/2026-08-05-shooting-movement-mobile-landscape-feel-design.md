# 射击、移动与移动端横屏手感调整设计

## 目标

本轮集中解决 Demo 中最影响操作体验的四个问题：

- 射击需要过于精确地对准僵尸，斜向射击尤其容易擦空。
- 玩家与僵尸在画面中的占屏比例偏小。
- 移动速度、起步、转向和停止过于急促。
- 移动端摇杆偏小，并且竖屏状态仍可进入游戏。

完成后，射击仍然使用玩家明确输入的方向，不自动转向或吸附目标；命中容错完全由统一的物理命中盒提供。桌面端与移动端继续共享同一套移动和战斗逻辑。

## 当前基础与问题判断

- 跟随相机使用正交投影，`Camera3D.size` 为 `18.0`。
- 玩家移动速度为 `6.0`，地面加速度为 `42.0`，地面减速度为 `60.0`。玩家约 `0.14` 秒达到满速、`0.10` 秒停止。
- 手枪和步枪分别使用 `6°`、`5°` 的辅助角，并会在直接射线未命中可伤害对象时自动选择锥体内目标。
- 僵尸由头、躯干、左右侧面和腿部五个命中盒组成。横向联合范围较宽，但盒体前后深度主要为 `0.8～0.9` 米，不同观察方向的有效轮廓不一致。
- 五个部位分别带有伤害、击退和垂直抬升倍率，增加了命中盒放大后的重叠歧义。
- 移动端虚拟摇杆控件为 `208×208`，有效摇杆范围为 `164`，摇杆头为 `76`，死区比例为 `0.15`。
- 当前只有 Web 导出。移动浏览器，尤其 iOS 浏览器，不能保证由页面代码直接锁定设备方向。

## 方案选择

采用“统一圆柱命中盒 + 纯直线射击 + 正交相机拉近 + 统一移动调校 + 横屏守卫”的组合方案。

不采用以下方案：

- 不继续放大五个部位命中盒。放大后不同部位会严重重叠，射线命中的节点顺序可能影响伤害结果。
- 不保留辅助角或自动选择目标。玩家射出的方向必须与输入方向一致，不发生隐形拐弯。
- 不使用粗射线或球形扫掠代替普通射线。粗射线靠近掩体时更容易出现擦过障碍仍命中目标的歧义。
- 不直接缩放玩家和僵尸模型。现有角色世界尺寸约为 `1.8～1.9` 米，问题来自镜头取景，而不是模型尺寸本身。

## 统一射击命中

### 整体命中盒

将 `ZombieTarget` 当前五个部位 `Area3D` 替换为一个整体 `Area3D`，碰撞体明确使用 `CylinderShape3D`：

- 水平半径为 `1.1` 米。
- 总高度为 `2.2` 米。
- 中心高度为 `1.1` 米。
- 保持在武器射线使用的 Target 物理层。

圆形水平截面从正向、侧向和斜向都有一致半径，避免长方体前后深度较窄造成的方向性容错差异。该命中盒只用于枪械射击判定；僵尸行走、阻挡和击退仍使用现有 `MotionCollision`，不扩大实体碰撞范围。

### 统一伤害与反馈

所有枪械命中都使用当前武器定义中的基础伤害，不再根据头、躯干、侧面或腿部应用倍率：

- `critical` 始终为 `false`。
- 命中区域统一记为 `&"body"`。
- 击退倍率和垂直抬升使用一套固定值。
- HUD 只显示普通 `HIT` 或 `KILL`，不再显示 `CRITICAL`。

`HitResult` 可以保留现有字段，以避免扩大本轮重构范围，但 Zombie 的统一命中路径不再产生暴击结果。

### 移除瞄准辅助

枪械只执行一次从稳定功能起点沿 `aim_direction` 的普通物理射线：

1. 输入系统产生移动与射击方向。
2. 武器把方向归一化到水平面。
3. 射线沿该方向发射到武器最大射程。
4. 射线命中整体 Zombie 命中盒时结算统一伤害。
5. 未命中时直接产生 miss，不再搜索附近目标或改写射线终点。

删除武器定义中的辅助角和辅助距离配置，以及 `RangedWeapon` 的候选目标选择路径。`AimAssistMath` 若没有其他消费者，则连同对应测试一起移除。

## 相机与移动手感

### 正交相机拉近

将 `FollowCamera/Camera3D.size` 从 `18.0` 调整为 `15.0`，保持当前位置、俯角、轴对齐方向、跟随平滑和射击镜头脉冲不变。

该改动同时放大玩家、僵尸、射击反馈和场景道具，不改变任何世界碰撞尺寸。场地边界仍大于可视区域，相机会继续跟随玩家展示其附近战斗空间。

### 移动参数

第一轮参数调整为：

| 参数 | 当前值 | 目标值 |
| --- | ---: | ---: |
| `move_speed` | `6.0` | `5.0` |
| `ground_acceleration` | `42.0` | `30.0` |
| `ground_deceleration` | `60.0` | `42.0` |

空中加速度、重力和跳跃速度保持不变。本轮只调整地面移动，不重做跳跃或动画系统。

键盘输入仍提供完整强度，移动摇杆继续使用模拟强度控制实际速度。`PlayerMotion.world_direction()` 保持对角方向归一化，确保斜向最大速度不超过直线最大速度。

## 移动端摇杆

放大 `MobileControls/Layout/VirtualJoystick`：

| 参数 | 当前值 | 目标值 |
| --- | ---: | ---: |
| 控件尺寸 | `208×208` | `252×252` |
| `joystick_size` | `164` | `204` |
| `tip_size` | `76` | `88` |
| `deadzone_ratio` | `0.15` | `0.12` |

摇杆继续固定在横屏左下角，布局偏移明确调整为 `left=40`、`top=-292`、`right=292`、`bottom=-40`。开火和跳跃按钮本轮不放大、不移动；集成测试负责确认三者矩形不重叠。

更大的有效行程用于提升小幅方向修正能力；较低死区让轻推更早产生移动。摇杆仍直接驱动现有四个 InputMap 动作，不新增移动端专用玩家逻辑。

## 移动端横屏守卫

### 平台行为

新增可复用的移动端横屏守卫，并同时用于主菜单和 Demo：

- 非触屏桌面环境不显示、不改变暂停状态。
- 触屏设备横屏时正常运行。
- 触屏设备竖屏时显示覆盖整个画面的遮罩，提示“请旋转设备横屏游玩”。
- 竖屏期间暂停游戏并阻止移动、射击、跳跃和菜单点击。
- 设备恢复横屏后自动移除遮罩并恢复之前由守卫触发的暂停状态。

当前项目以 H5 为主要移动端目标。由于移动浏览器不能可靠强制旋转设备，设计中的“强制横屏”定义为：竖屏时不能游玩，只有横屏后才能继续。未来增加 Android 或 iOS 原生导出时，再在对应导出预设中设置原生 landscape orientation；本轮不创建不存在的原生导出配置。

### 状态边界

横屏守卫自身必须在场景暂停时继续处理窗口尺寸变化。进入竖屏时，只有在场景树原本未暂停的情况下才设置暂停并记录 `paused_by_guard = true`；恢复横屏或守卫退出树时，也只有该标记为 `true` 才恢复运行。这样不会覆盖其他系统主动设置的暂停状态。

移动控件在进入竖屏阻断、应用失焦或暂停时释放所有动作，避免恢复横屏后保留移动或持续开火输入。

## 组件边界

- `ZombieTarget.tscn`：定义统一射击命中盒和保持独立的移动碰撞体。
- `zombie_hitbox.gd` / `zombie_target.gd`：转发并结算统一伤害、击退和普通命中结果。
- `ranged_weapon.gd`：只负责直线射线、统一命中调用和射击反馈，不搜索辅助目标。
- 武器资源：只保留射程、伤害、射速、碰撞层、后坐和视觉参数。
- `FollowCamera.tscn`：保存新的正交尺寸。
- `player_controller.gd` / `player_motion.gd`：保存移动参数并维持键盘、摇杆共享的归一化移动。
- `MobileControls.tscn`：保存放大后的摇杆尺寸、行程、摇杆头和死区。
- 新的横屏守卫场景与脚本：检测触屏和宽高比，管理遮罩与自身暂停状态，不拥有游戏玩法逻辑。

## 错误与边界处理

- Zombie 整体命中盒缺失时，场景契约测试必须失败；运行时不添加自动生成碰撞体的隐藏降级逻辑。
- 射击方向为零向量时继续使用现有稳定默认方向，避免创建无长度射线。
- 多只僵尸命中盒重叠时，Godot 射线仍只结算距离起点最近的第一个碰撞体。
- 整体命中盒不能加入 World 碰撞层，避免扩大后阻挡玩家或其他僵尸移动。
- 竖屏遮罩必须覆盖安全区域外的整个视口，并在窗口旋转、浏览器地址栏伸缩和画布尺寸变化后重新判断。
- 桌面上启用鼠标模拟触摸不能误触发横屏限制；触屏判断沿用当前物理触屏检测策略。
- 横屏守卫被移出场景树时，如果暂停由它触发，必须恢复场景树状态。

## 测试策略

所有行为修改先添加失败测试，再修改生产代码。

### 射击与命中

- Zombie 只暴露一个供枪械使用的整体命中 `Area3D`。
- 整体碰撞体为水平圆形，半径和高度满足宽松命中下限。
- 头部高度、躯干高度和腿部高度命中都产生相同伤害、非暴击结果和相同击退倍率。
- 枪械资源不再包含辅助角和辅助距离。
- 直接射线 miss 时不会自动改写终点或选择附近目标。
- HUD 不再进入 `CRITICAL` 显示路径。

### 相机与移动

- FollowCamera 正交尺寸为 `15.0`，位置和俯角保持现有值。
- 玩家地面移动默认参数为 `5.0 / 30.0 / 42.0`。
- 直线和斜向输入达到相同最大速度。
- 停止输入后按新的减速度平滑归零。
- 模拟摇杆的部分强度继续产生对应比例的移动输入。

### 移动端 UI 与横屏

- 虚拟摇杆控件、有效范围、摇杆头和死区符合目标参数。
- 放大后的摇杆与开火、跳跃按钮矩形不重叠。
- 非触屏环境不启用横屏遮罩。
- 触屏横屏状态允许游戏运行。
- 触屏竖屏状态显示遮罩、暂停游戏并释放全部触控动作。
- 从竖屏恢复横屏后隐藏遮罩，只撤销守卫自身造成的暂停。

### 完整验证

运行 Godot headless 编辑器导入检查和完整自定义测试套件。人工验收需分别覆盖桌面键盘和移动端触屏，并重点测试八个主要方向的射击与移动。

## 人工验收标准

1. 不靠自动吸附，沿任意方向射出的弹道都与玩家输入方向一致。
2. 正向、侧向和斜向瞄准僵尸边缘时，命中容错体感基本一致。
3. 命中僵尸任何可见部位都造成相同伤害，不出现暴击提示。
4. 玩家和僵尸在画面中明显大于当前版本，但相机仍能展示足够的近身战斗空间。
5. 移动起步、变向和停止比当前版本平缓，斜向速度不额外增加。
6. 移动端摇杆明显更大，拇指小幅移动可以稳定控制方向和速度。
7. 移动端竖屏不能操作游戏，旋转到横屏后自动恢复。

## 非目标

- 鼠标自由瞄准、右摇杆独立瞄准或双摇杆射击。
- 自动锁敌、辅助角、磁性子弹或目标优先级系统。
- 爆头、弱点、护甲或部位破坏。
- 修改僵尸实体移动碰撞尺寸或避障行为。
- 重新设计开火、跳跃按钮的视觉样式。
- 为尚未存在的 Android、iOS 原生导出创建完整发布配置。
