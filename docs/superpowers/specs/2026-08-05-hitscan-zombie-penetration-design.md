# Hitscan 枪械僵尸穿透设计

## 背景

当前手枪和步枪使用即时射线命中的 Hitscan 架构。每次开枪先计算包含水平散布的最终方向，再从胶囊枪口端点执行一次 `PhysicsRayQueryParameters3D` 查询，只处理最近碰撞体。`ShotTracer` 仅负责视觉曳光，不参与碰撞或伤害。

僵尸可受击区域位于物理层 4，场景地面、墙体、集装箱等建筑碰撞位于物理层 1。当前射线同时查询这两个层，因此建筑可以阻挡枪械伤害。本功能在保留该 Hitscan 架构和建筑阻挡规则的前提下，让同一条直线上的多个僵尸依次受到衰减伤害。

## 目标

- 手枪和步枪分别配置穿透伤害系数与最大额外穿透数量。
- 首个僵尸承受武器的完整基础伤害。
- 后续僵尸的伤害按穿透系数逐次递乘。
- 同一发射击最多命中 `1 + max_penetration_count` 个僵尸。
- 建筑、墙体及其他非僵尸场景碰撞立即截断穿透。
- 同一僵尸即使存在多个 Hitbox，也只能被同一发射击伤害一次。
- 保持现有散布、射程、射速、枪口位置、后坐力、相机反馈、声音、击退、血液效果和曳光对象池行为。

## 非目标

- 不改为实体子弹，不增加飞行时间、重力下坠或弹速。
- 不增加跳弹、护甲穿透、材质穿透或建筑耐久。
- 不修改近战武器。
- 不增加穿透专属 UI、音效或 VFX。
- 不调整僵尸生命值、命中区倍率或武器现有基础伤害。
- 不修改第三方 `addons/`。

## 参数语义

`RangedWeaponDefinition` 增加以下字段：

- `penetration_damage_coefficient: float`：每穿过一个僵尸后，下一目标伤害乘以该系数，导出范围为 `0.0–1.0`。
- `max_penetration_count: int`：首个目标之后最多还能穿透的额外僵尸数量，最小值为 `0`。

第 `n` 个僵尸的理论伤害为：

```text
damage(n) = base_damage × penetration_damage_coefficient^(n - 1)
```

其中首个僵尸的 `n = 1`，因此始终承受 `base_damage`。最大僵尸命中数为：

```text
max_zombie_hits = 1 + max_penetration_count
```

首轮调校值：

| 武器 | 基础伤害 | 穿透系数 | 最大额外穿透 | 最多命中僵尸 |
|---|---:|---:|---:|---:|
| 手枪 | `35.0` | `0.5` | `1` | `2` |
| 步枪 | `25.0` | `0.75` | `3` | `4` |

示例：手枪连续命中两个僵尸时，理论伤害依次为 `35.0`、`17.5`；步枪连续命中四个僵尸时，理论伤害依次为 `25.0`、`18.75`、`14.0625`、`10.546875`。目标剩余生命不足时，`HitResult.damage_applied` 仍使用生命组件返回的实际伤害。

系数为 `0.0` 时，首个僵尸正常受伤，弹道在该僵尸处停止，不继续执行无有效伤害的查询。最大额外穿透为 `0` 时，行为等价于当前只命中首个僵尸的射线。

## Hitscan 穿透流程

每次开枪仍然只计算一条最终射击直线。`RangedWeapon` 使用同一个枪口原点、散布后方向和射程终点循环查询最近碰撞体：

1. 排除持枪玩家自身 RID，查询当前最近碰撞体。
2. 若没有碰撞体，弹道终点为武器最大射程，结束查询。
3. 从碰撞体向父节点查找 `damageable_targets` 组中的僵尸实体。
4. 若找到尚未处理的僵尸：
   - 使用当前穿透伤害调用僵尸现有 `apply_hit()`；
   - 记录该僵尸实体 ID，保证同一发只结算一次；
   - 将本次碰撞体 RID 加入排除集合；
   - 该僵尸占用一个允许命中的目标位置，即使它已处于无法承受伤害的死亡状态；
   - 达到最大僵尸命中数或下一段伤害为零时，以当前命中点作为弹道终点并结束；
   - 否则把当前伤害乘以穿透系数，继续查询同一直线上的最近碰撞体。
5. 若命中同一僵尸的另一个 Hitbox，只排除该 Hitbox RID，不重复伤害、不重复计数，然后继续查询。
6. 若碰撞体不属于僵尸：
   - 保留既有兼容行为，对支持 `apply_hit()` 或 `apply_damage()` 的非僵尸对象最多结算一次完整基础伤害；
   - 无论是否可受伤，都以该碰撞点作为弹道终点并立即停止，不允许穿透。

每次循环都从原始枪口到原始射程终点执行查询，并扩大排除集合，而不是把起点推进到碰撞体内部。这样可以避免从 Area 或薄碰撞体内部继续发射造成重复命中，同时仍由物理世界按距离决定僵尸和建筑的真实先后顺序。

## 僵尸识别与去重

穿透资格不根据“碰撞体是否拥有 `apply_hit()`”判断，而是复用项目现有近战目标解析约定：从碰撞体开始向父节点遍历，找到第一个属于 `damageable_targets` 组的 `Node3D`。

- 找到该实体：视为可穿透僵尸。
- 未找到该实体：视为不可穿透对象。
- 使用僵尸实体的 `instance_id` 去重。
- 使用每个已遇到的 `CollisionObject3D` RID 扩大射线排除集合。

该规则允许未来为同一僵尸增加头部、身体等多个 Hitbox，而不会让一发子弹在同一实体上重复伤害；不同僵尸仍按射线距离顺序独立计数。

## 伤害与受击效果

每个首次命中的僵尸都独立调用现有 `apply_hit(amount, hit_position, shot_direction)`。因此以下行为由僵尸当前实现自然执行，不增加穿透专用分支：

- 生命扣减；
- 击退方向与力度；
- 受击或死亡动画；
- 血液冲击、地面血迹和击退血迹；
- 每个目标各自的死亡判断。

穿透只衰减伤害值，不衰减击退、受击动画或血液强度。本轮不增加独立的穿透击退系数。

## 汇总 `HitResult`

一次开枪继续只发送一次 `attack_resolved`，避免修改 `WeaponBase`、`EquipmentController`、`PlayerController`、相机和 HUD 的信号接口。

循环查询期间把各目标返回的有效 `HitResult` 汇总为单个射击结果：

- `did_hit`：任一目标返回有效命中时为 `true`。
- `damage_applied`：所有有效命中的实际伤害总和。
- `critical`：任一有效命中为暴击时为 `true`。
- `killed`：任一有效命中造成死亡时为 `true`。
- `hit_zone`：使用最后一个有效命中的命中区。
- `position`：使用最后一个有效命中的命中位置。

若没有目标返回有效命中，则返回以弹道终点为位置的 `HitResult.miss()`。HUD 因而继续显示一次 `HIT`，并在任意穿透目标死亡时显示一次 `KILL`；相机冲击和视觉后坐仍每发只触发一次。

## 曳光与单次射击反馈

每次开枪仍只从对象池取得一条 `ShotTracer`。曳光连接枪口原点和弹道实际终点：

- 命中建筑或其他不可穿透对象：结束在该碰撞面。
- 达到最大僵尸命中数：结束在最后一个允许命中的僵尸。
- 穿透系数为零：结束在首个僵尸。
- 穿过允许数量内的僵尸后没有其他碰撞：延伸到武器最大射程。

枪口火焰、射击声音、视觉后坐、相机冲击和 `attack_resolved` 每次开枪仍只触发一次。所有目标的 `apply_hit()` 继续使用本发散布解析后的同一个 `shot_direction`，保证伤害方向、击退和曳光位于同一条 Hitscan 直线上。

## 与现有弹道扩散改动的兼容

当前工作区包含进行中的渐进式随机散布实现。本功能必须在散布解析之后执行，不创建第二条方向：

```text
玩家朝向 → WeaponSpreadState 解析最终方向 → 穿透射线循环 → 逐目标伤害
```

穿透过程中不得重新采样随机数或修改方向。所有重复查询共享 `_fire()` 本次得到的 `ray_origin`、`ray_direction` 和 `ray_end`，因此不会让后续目标偏离首个目标所在的真实弹道。

## 异常与安全边界

- 穿透系数在运行时限制到 `0.0–1.0`，最大额外穿透限制为不小于 `0`，防止外部脚本绕过 Inspector 范围。
- 每次遇到新的碰撞体都必须把其 RID 加入排除集合，确保循环持续前进。
- 查询次数由射线实际遇到的有限碰撞体数量和最大僵尸命中数共同限制；不得使用无界重试。
- 持枪玩家或射线世界无效时沿用现有生命周期前置条件，不新增静默伪造命中。
- 零长度曳光继续由 `ShotTracer.setup()` 的既有保护处理。
- 非僵尸对象永远不会因为实现了伤害方法而获得穿透资格。

## 文件职责

- `scripts/combat/weapons/ranged_weapon_definition.gd`
  - 定义穿透伤害系数与最大额外穿透参数。
- `resources/weapons/pistol.tres`
  - 配置手枪 `0.5 / 1` 的穿透参数。
- `resources/weapons/rifle.tres`
  - 配置步枪 `0.75 / 3` 的穿透参数。
- `scripts/combat/weapons/ranged_weapon.gd`
  - 循环执行同一直线上的最近碰撞查询、识别并去重僵尸、逐次衰减伤害、汇总结果以及确定曳光终点。
- `tests/unit/test_weapon_configuration.gd`
  - 验证两把枪的穿透配置与参数语义。
- `tests/unit/test_weapon_feedback.gd`
  - 验证多目标衰减、最大数量、墙体阻挡、Hitbox 去重、汇总结果、曳光终点和单次反馈契约。
- `tests/test_runner.gd`
  - 仅在新增独立测试文件时注册；若扩展现有测试则无需修改。

## 测试策略

遵循项目现有 Headless Godot 测试方式，不使用 CUA 或 UI 自动化。

### 武器配置测试

扩展 `tests/unit/test_weapon_configuration.gd`：

- 手枪穿透系数为 `0.5`，最大额外穿透为 `1`。
- 步枪穿透系数为 `0.75`，最大额外穿透为 `3`。
- 两个字段存在于 `RangedWeaponDefinition`，近战定义不受影响。

### 射击集成测试

扩展 `tests/unit/test_weapon_feedback.gd`，使用确定的直线方向和场景节点验证：

- 手枪对两个直线僵尸依次造成 `35.0` 与 `17.5` 理论伤害，第三个僵尸不受伤。
- 步枪对四个直线僵尸依次使用 `25.0`、`18.75`、`14.0625`、`10.546875` 理论伤害，第五个僵尸不受伤。
- 僵尸之间存在墙体时，墙后的僵尸不受伤，曳光终点位于墙面。
- 同一僵尸增加第二个 Hitbox 后仍只扣除一次生命，且不额外消耗穿透数量。
- `attack_resolved` 每次开枪只发出一次，汇总实际伤害并传播任意击杀状态。
- 枪口火焰、声音、散布增长和曳光对象池游标每发只推进一次。
- 未遇到阻挡且未达到数量上限时，曳光延伸到最大射程；达到上限时结束在最后一个允许目标。
- 非僵尸可受伤对象保留单次伤害但阻断后续穿透。

必须保持现有枪械散布、墙体净空、射击反馈、僵尸受击和项目契约测试通过。

## 验收标准

1. 手枪首个僵尸承受 `35.0` 理论伤害，第二个承受 `17.5`，最多命中两个僵尸。
2. 步枪首个僵尸承受 `25.0` 理论伤害，后续依次乘 `0.75`，最多命中四个僵尸。
3. 所有目标位于同一条散布后的 Hitscan 直线上，穿透过程不改变方向。
4. 墙体、建筑及其他非僵尸对象立即截断射线，后方僵尸不受伤。
5. 同一僵尸的多个 Hitbox 不会造成重复伤害或重复穿透计数。
6. 每个僵尸独立产生当前已有的伤害、击退、血液和死亡效果。
7. 一次开枪只产生一次枪口火焰、声音、曳光、后坐力、相机冲击和 `attack_resolved`。
8. 汇总结果包含所有实际伤害，并在任意目标死亡时向 HUD 报告击杀。
9. 原有弹道扩散、墙体净空与 Hitscan 行为不发生回归。
10. Godot Headless 编辑器解析检查与完整测试套件全部通过。
