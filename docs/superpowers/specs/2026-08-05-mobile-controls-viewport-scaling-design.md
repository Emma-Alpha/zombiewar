# 移动端控件视口比例缩放设计

## 背景

当前移动端摇杆使用固定 `252×252` 尺寸，开火键使用固定 `160×160` 尺寸。它们在项目基准视口 `1280×720` 下分别约占屏幕高度的 `35%` 和 `22.2%`，但在不同横屏视口高度下不会保持一致的触控面积比例。

本次调整让移动端摇杆和开火键在运行时根据视口高度布局，使不同横屏尺寸拥有一致的操作手感。竖屏仍由现有 `MobileOrientationGuard` 阻止游玩，不改变其暂停和输入取消行为。

## 目标

- 摇杆控件的宽高始终等于当前视口高度的 `45%`。
- 开火键保持当前 `160:252` 的摇杆尺寸比例，宽高约等于视口高度的 `28.57%`。
- 摇杆内部有效行程、摇杆头和边距随摇杆控件同比缩放。
- 开火键文字和轮廓随开火键同比缩放，避免按钮放大后视觉元素显得偏小。
- 跳跃键保持当前 `120×120` 尺寸，仅调整位置以避开放大后的开火键。
- 视口尺寸变化后自动重新布局，触控输入和横竖屏恢复行为保持稳定。

## 非目标

- 不改变摇杆死区、输入动作映射或移动速度。
- 不放大跳跃键。
- 不修改桌面端控制方式或桌面帮助提示。
- 不新增移动端设置界面或用户自定义缩放选项。

## 方案

### 运行时比例布局

`MobileControls` 在 `_ready()` 时读取 `get_viewport().get_visible_rect().size.y`，并监听视口的 `size_changed` 信号。初始化及视口变化时统一调用响应式布局方法。

布局使用以下基准和比例：

| 项目 | 计算方式 | 1280×720 下的结果 |
| --- | --- | --- |
| 摇杆控件宽高 | `viewport_height × 0.45` | `324` |
| 摇杆有效行程 | `joystick_control_size × 204 / 252` | 约 `262.29` |
| 摇杆头尺寸 | `joystick_control_size × 88 / 252` | 约 `113.14` |
| 开火键宽高 | `joystick_control_size × 160 / 252` | 约 `205.71` |
| 左右及底部边距 | `viewport_height × 40 / 720` | 约 `51.43` |
| 摇杆死区 | 固定 `0.12` | `0.12` |

摇杆固定在左下角，开火键固定在右下角。两者使用相同的响应式屏幕边距。

### 跳跃键避让

跳跃键继续保持 `120×120`。它位于开火键左上方，并基于视口高度缩放两者之间的间距。布局保证摇杆、开火键和跳跃键的触控矩形互不重叠。

### 开火键视觉缩放

开火键标签字号以当前 `26px` 和 `252px` 摇杆基准同比缩放。`MobileActionButton` 的圆形内缩和轮廓宽度允许按按钮布局比例设置；开火键使用缩放值，跳跃键继续使用当前视觉参数。

## 组件改动

### `scripts/ui/mobile_controls.gd`

- 保存视口比例常量和现有控件基准比例。
- 新增单一响应式布局入口，负责计算并应用摇杆、开火键和跳跃键的尺寸与位置。
- 在节点就绪后连接视口尺寸变化信号并立即布局。
- 退出树时安全断开信号，避免重复连接或悬空回调。
- 保持现有触控 ID、动作取消和横竖屏输入处理逻辑不变。

### `scripts/ui/mobile_action_button.gd`

- 将圆形内缩和轮廓宽度从固定绘制值改为可设置属性。
- 默认值保持当前视觉效果，使跳跃键和其他潜在实例不受影响。

### `scenes/ui/MobileControls.tscn`

- 保留动作映射、节点结构和基础场景值。
- 运行时尺寸与偏移由 `MobileControls` 覆盖，不依赖固定像素完成最终布局。

## 数据流

1. `MobileControls` 进入场景树并完成节点就绪。
2. 读取当前可见视口高度。
3. 根据固定比例计算摇杆、开火键、内部视觉尺寸、边距和跳跃键位置。
4. 将计算结果写入现有控件属性。
5. 视口触发 `size_changed` 时重复步骤 2–4。
6. 输入继续通过现有 `VirtualJoystick` 和 `MobileActionButton` 驱动 InputMap。

## 边界处理

- 仅对大于零的视口高度应用布局，避免场景初始化中的无效尺寸覆盖已有场景值。
- 横屏比例不设置固定像素上限或下限，以满足“不同横屏尺寸保持相同比例”的要求。
- 竖屏阶段仍可完成布局计算，但 `MobileOrientationGuard` 继续遮罩、暂停并取消输入；恢复横屏后按新视口重新布局。

## 测试

- 在 `1280×720` 子视口中断言摇杆为 `324×324`，开火键约为 `205.71×205.71`，摇杆内部尺寸符合比例，死区仍为 `0.12`。
- 将同一子视口切换为另一种横屏尺寸，断言控件尺寸随视口高度重新计算。
- 断言摇杆、开火键和跳跃键矩形互不重叠，且跳跃键仍为 `120×120`。
- 保留并运行原始触控测试，验证摇杆拖动、开火按下和释放、多点触控及横竖屏输入取消仍然有效。
- 运行完整 headless 测试套件，并用 Godot headless editor 检查场景和脚本解析。

## 验收标准

- 任意受支持的横屏视口中，摇杆宽高均为视口高度的 `45%`。
- 开火键与摇杆保持 `160:252` 的尺寸比例。
- 视口尺寸改变后无需重载场景即可更新布局。
- 三个移动端触控目标不重叠。
- 跳跃键尺寸、输入动作映射、摇杆死区和横屏守卫行为没有回归。
