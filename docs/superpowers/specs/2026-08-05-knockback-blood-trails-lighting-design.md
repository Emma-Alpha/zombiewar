# 击退血液拖痕与光照设计

## 目标

本轮只重做命中后的血液表现，不实现血迹清理功能。

完成后，每次有效射击命中都以真实命中世界坐标为起点：地面上先形成一块明显的大面积血斑，僵尸随后沿实际击退路径留下有限、连续但不规则的拖痕。所有持久血迹都参与当前 3D 光照与阴影计算，僵尸、玩家和场景模型投下的动态阴影可以自然压暗血迹；血迹不使用不受光照影响的纯贴图颜色。

## 当前基础与问题判断

- `ZombieTarget.apply_hit()` 已能获得真实 `hit_position`、射击方向、伤害和击退倍率。
- 当前 `BloodImpact` 使用面向相机的 `Sprite3D` 与一次性粒子，只存在约 `0.45` 秒，适合作为瞬时命中喷溅，不适合作为持久拖痕。
- 当前 `GroundBloodManager.spawn_hit_splat()` 会在命中点沿射击方向随机偏移 `0.35～0.9` 米，只生成一块小血迹，因此血斑既不严格对应真实命中位置，也不能反映僵尸实际击退路径。
- 当前持久血迹使用 `Sprite3D`，场景没有启用受光材质契约，无法保证它与场景模型使用同一套光照和阴影结果。
- 管理器已有 `192` 个血迹实例上限和 FIFO 复用基础，可以继续作为全局性能边界。
- 项目使用 Godot 4.7.1 的 GL Compatibility 渲染器。本轮不能为了血迹切换到 Forward+，以免改变 Web 与移动端兼容性。

## 方案选择

采用“受光薄网格血迹 + 实际击退位移采样 + 空间覆盖合并”的方案。

不采用以下方案：

- 不使用 `Decal3D` 作为主实现。它对渲染后端和移动端路径要求更高，并且本轮只需要地面血迹，不值得切换渲染器。
- 不把血液动态绘制进整张地面 RenderTexture。该方案可以得到完全连续的轨迹，但会引入纹理坐标、分辨率、边界和持久化管理复杂度。
- 不继续用不受光照影响的 `Sprite3D` 叠图。它无法满足模型阴影覆盖血迹的视觉要求。
- 不在本轮增加血迹清理按键、HUD 按钮或移动端清理交互。

## 命中血斑

### 真实位置

有效命中后，以武器结算得到的 `hit_position` 为唯一命中起点。管理器从该坐标垂直向下查询 `blood_surface`，把血迹落在真实命中点正下方的可接受地面上，不再沿射击方向添加随机位置偏移。

命中点下方没有 `blood_surface` 时，只保留现有瞬时空中喷溅，不在错误的远处补生成地面血迹。

### 大面积起始血斑

普通命中生成一块横向尺寸约 `0.9～1.25` 米的主血斑；高击退倍率可以把上限放大到约 `1.4` 米，但不能超过该上限。主血斑使用不规则透明轮廓，朝向以射击水平分量为基准，再叠加小幅随机旋转，使血量方向与冲击方向相关但不显得机械。

死亡命中仍可生成更大的终点血池，但必须复用相同的受光材质、投影和覆盖合并规则。死亡血池不能绕过全局实例上限。

## 击退拖痕

### 实际位移采样

拖痕只记录命中后由击退产生的短时移动，不记录僵尸正常追击、游荡或攻击位移。

`ZombieTarget` 在应用有效击退时开启一次拖痕会话，并保存本次强度、上一帧位置、累计距离和最大持续时间。每次 `move_and_slide()` 完成后，使用移动前后的真实世界位置生成一段位移样本。这样碰撞、墙体阻挡和斜向滑动都会自然反映在拖痕路径中，而不是根据最初射击方向猜测轨迹。

拖痕会话在以下任一条件满足时停止：

- 持续时间达到 `0.75` 秒。
- 已生成 `8` 个拖痕印记。
- 水平速度下降到正常追击速度附近，且已至少生成一个印记。
- 僵尸死亡并离开场景树。

新的有效命中会重置拖痕会话，并以新的真实命中位置和击退强度为准，避免多个独立计时器同时驱动同一只僵尸。

### 采样形状

管理器沿实际位移段每隔约 `0.32～0.42` 米放置一个拖痕印记。跨越多个间距的一帧位移必须在段内插值补齐，不能因为低帧率留下明显断层。

每个拖痕印记沿局部移动方向拉长：

- 宽度约 `0.28～0.45` 米。
- 长度约 `0.5～0.8` 米。
- 越靠近拖痕末端，尺寸和透明度越小。
- 旋转以真实位移方向为主，只允许小幅随机偏差。

拖痕开始位置与大面积主血斑可以轻微重叠，以形成“冲击血斑被身体向后拖开”的连续关系。

## 有限叠加与持久化

血迹在当前 Demo 生命周期内持续保留，不按时间自动淡出。全局仍最多维护 `192` 个持久血迹实例，达到上限后继续使用现有 FIFO 复用思路。

为避免同一位置不断堆叠透明面片，`GroundBloodManager` 按地面水平坐标划分约 `0.45` 米的空间格：

- 每个格子最多允许两个独立可见血迹实例。
- 第一个实例提供基础覆盖，第二个实例允许轻微错位和旋转，形成自然叠加。
- 第三个及后续请求不再创建新实例，而是合并到格子中较匹配的现有实例：相对该实例最近一次 `setup()` 基础尺寸的累计增幅最多约 `15%`，不能每次请求再乘一次增长；颜色最多加深到预设下限，透明度不得持续累加到完全不透明。
- 复用某个实例时，必须先从其旧格子索引移除，再注册到新格子，避免空间索引保留失效引用。

该规则同时用于主血斑、拖痕和死亡血池，确保“可以稍微叠加，但不会一直叠加”。

## 光照与阴影

### 几何与材质

持久血迹由贴近地面的薄型 `MeshInstance3D` 表示，网格法线与命中表面法线一致，并保持约 `0.01` 米表面偏移以避免 Z-fighting。血迹只用于地面视觉，不参与物理碰撞。

血迹材质必须满足以下契约：

- 使用透明血迹纹理的 alpha 轮廓，并启用适合 GL Compatibility 的透明深度处理。
- 使用受光空间材质，不启用 `unshaded`。
- 使用非金属材质；新鲜主血斑的粗糙度略低，拖痕粗糙度略高，产生克制的湿润高光差异。
- `MeshInstance3D` 不投射自身阴影，避免一张薄面片在地面上产生悬浮黑边。
- 血迹仍接收 DirectionalLight3D 和其他 Light3D 的漫反射、镜面反射与阴影结果。

因此，当僵尸或其他模型挡住主光源时，其阴影会像压在普通地面材质上一样覆盖血迹；当模型移开时，血迹恢复到当前环境光和主光下的颜色。代码不额外伪造屏幕空间阴影，也不根据模型位置手工修改血迹颜色。

### 纹理来源

继续使用 Kenney Splat Pack（CC0）作为血迹轮廓来源。本轮从同一包中再选择 `2～3` 张透明喷溅纹理：

- 较完整、面积较大的轮廓用于主血斑和死亡血池。
- 带方向性尖角或断裂边缘的轮廓用于非均匀缩放后的拖痕。
- 纹理保持原始透明像素，通过受光材质统一着色为深红色，不直接修改第三方源文件。

Quaternius 没有专用血液贴图；Poly Haven 的 `blood` 纹理搜索为 `0` 个结果，因此本轮不从这两个站点新增血迹资源。

## 组件边界与数据流

### `ZombieTarget`

- 继续负责伤害、击退速度、碰撞移动和瞬时 `BloodImpact`。
- 有效命中时发出真实主血斑请求，并开启一次击退拖痕会话。
- 在 `move_and_slide()` 后发出真实位移段，不负责创建或复用血迹节点。
- 正常 AI 移动不能产生拖痕。

### `GroundBloodManager`

- 接收主血斑、死亡血池和击退位移段请求。
- 负责向 `blood_surface` 投影、间距插值、纹理变体选择、尺寸与方向计算。
- 负责空间格覆盖合并、`192` 实例上限、FIFO 复用和失效索引清理。
- 对外提供确定性的放置入口，随机量只影响纹理、轻微旋转、尺寸和色调变化。

### `GroundBloodSplat`

- 从 `Sprite3D` 改为持有薄网格与受光材质的专用节点。
- 接收世界位置、表面法线、二维尺寸、旋转、纹理变体、色调和粗糙度。
- 负责更新自身变换和材质参数，不负责决定何时生成或是否合并。

### `DemoArena`

- 继续把动态生成的每只僵尸接到唯一 `GroundBloodManager`。
- 本轮不新增清理输入、HUD 文案或按钮。

数据流为：

1. 武器射线返回真实 `hit_position`。
2. `ZombieTarget.apply_hit()` 结算伤害与击退，并请求主血斑。
3. 管理器把真实命中坐标垂直投影到地面，放置或合并大面积血斑。
4. 僵尸完成每帧碰撞移动后报告真实位移段。
5. 管理器沿位移段按间距补点，生成或合并受光拖痕。
6. 拖痕会话停止后，僵尸恢复正常移动且不再产生血迹。

## 错误与边界处理

- 射击方向水平分量为零时，主血斑使用僵尸当前朝向作为稳定方向；仍不能随机改变落点。
- 单帧位移小于采样间距时累积距离，不立即生成重复印记。
- 单帧位移跨越多个采样间距时最多补到本次会话剩余印记数量，不能突破每次命中的 `8` 个上限。
- 投影射线只接受 `blood_surface`；命中僵尸、玩家或普通道具时继续排除并向下查询，不能把持久血迹贴到角色碰撞体上。
- 表面法线无效时使用 `Vector3.UP`；找不到地面时跳过该印记，不创建悬空血迹。
- 僵尸在拖痕会话中被删除时，管理器和空间索引不能保留对该节点的强引用。
- FIFO 复用与格子合并同时发生时，以合并现有格子为优先；只有需要新视觉实例时才进入实例池获取流程。
- 所有随机变化必须处于设计范围内，不能改变真实命中坐标、实际位移路径、每格两层和每次八段的硬限制。

## 测试策略

所有生产行为修改先添加失败测试，再进入实现。

### 采样与覆盖单元测试

- 真实命中投影不包含沿射击方向的位置随机偏移。
- `1.0` 米直线位移可以按目标间距生成多个有序插值点。
- 多帧短位移会累计到下一次采样点，不在原地连续生成印记。
- 斜向位移生成的拖痕方向与实际位移方向一致。
- 单次拖痕会话不会超过 `8` 个印记或 `0.75` 秒。
- 正常 AI 移动且没有活动击退会话时不请求拖痕。
- 同一空间格前两次请求可以占用两层，第三次请求执行有限扩大或加深，不增加实例数。
- FIFO 复用后旧格子不再引用已移动的血迹实例。

### 场景与材质契约测试

- `GroundBloodSplat` 使用 `MeshInstance3D` 而不是持久 `Sprite3D`。
- 血迹网格拥有透明纹理和受光材质，材质不是 unshaded。
- 血迹实例不投射阴影，但保持可接收场景光照和阴影的材质路径。
- 主血斑支持非均匀二维尺寸，拖痕可以沿移动方向拉长。
- `DemoArena` 仍只拥有一个上限为 `192` 的 `GroundBloodManager`，且没有新增清理输入依赖。
- 每只初始和动态生成的僵尸都连接主血斑与拖痕请求。

### 完整验证

运行 Godot headless 编辑器导入检查和完整自定义测试套件。人工验收时在 Demo 中连续从不同方向射击僵尸，观察真实起点、碰撞后的轨迹、重叠上限、低帧率连续性和模型阴影覆盖效果。

## 人工验收标准

1. 子弹命中僵尸后，地面主血斑位于真实命中坐标正下方，不再向射击方向随机漂移。
2. 主血斑明显大于当前小血点，并保留不规则透明边缘。
3. 僵尸被击退、撞墙或沿障碍滑动时，拖痕遵循其真实移动路径。
4. 僵尸恢复正常追击或游荡后，不继续留下血迹。
5. 同一区域重复射击可以看到轻微叠加和颜色变化，但不会不断增加面片或变成纯黑块。
6. 血迹在 Demo 生命周期内持续保留，达到全局上限后平稳复用旧实例。
7. 僵尸、玩家或道具的动态阴影经过血迹时，血迹与周围地面一起自然变暗；阴影移开后恢复受光颜色。
8. 血迹边缘没有明显悬浮阴影、Z-fighting 或透明排序闪烁。

## 非目标

- 血迹清理按键、清理按钮、自动清场或按波次清理。
- 把持久血迹贴在僵尸身体表面或实现可流动的角色表面血液。
- 墙面、道具和任意曲面 Decal 投射。
- 切换 Forward+ 渲染器或改变现有 Web、移动端渲染后端。
- 体积血液、流体模拟、骨骼伤口、断肢或布料染色。
- 重做伤害数值、武器射速、击退强度、僵尸 AI 或死亡动画。
